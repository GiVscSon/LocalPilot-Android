# Обновление 0.6.3 Dev · проверяемое демо и поздний ACK

Срок700мс проверяется при отправке нового жеста. Для завершившегося жеста
`completionRejection` требует уже использованный билет и ту же привязку, приложение,
окно, размеры, корректное направление времени. Возраст билета после выполнения
не является причиной остановки. STOP и смена сессии по-прежнему отменяют продолжение.

В демо координаты кнопки обновляются через AccessibilityNodeInfo.refresh перед
каждым тапом. После Android ACK счёт тестовой игры читается заново; следующий тап
начинается только после прироста ровно на1. Выполнение10 команд больше не считается
доказательством10 попаданий. При отсутствии реакции через2с — DEMO_NO_TOUCH_RESPONSE.
Демо ограничено10 подтверждёнными касаниями и60с суммарно, с явным watchdog.
Постороннее увеличение счёта больше чем на1 останавливает тест. Не нажимайте цель
самостоятельно во время проверки.

Экспорт через «Экспорт задержек» содержит LAST_STOP; сам экспорт не стирает причину
предыдущей остановки. Например, билет/окно/перекрытие панели/таймаут различимы по коду.
Обновлённый instrumentation-тест по-прежнему требует счёт10 и остановку после STOP,
но допускает бюджет демо60с. Запуск этого теста на реальном Android пока не выполнен.

# Обновление 0.6.2 Dev

На Android14+ используется `MediaProjectionConfig.createConfigForDefaultDisplay()`:
запрашивается весь основной экран вместо выбора отдельного приложения. Обязательное
подтверждение Android остаётся; прошивка может изменять системный интерфейс.
На Android11–13 используется прежний системный запрос захвата экрана.

В развёрнутой панели и через «Экспорт задержек» показаны счётчики:
- кадры: принятые кадры текущей сессии;
- READ: обработанные результаты распознавания (включая неуспешные);
- решения: обращения к игровой стратегии, включая WAIT;
- ввод: жесты, принятые dispatchGesture;
- ACK: Android сообщил завершение жеста. Это ещё не подтверждает движение в игре.

При ошибке этапа панель разворачивается. Если нажатий нет, сохраните файл кнопкой
«Экспорт задержек» в главном окне LocalPilot. Данные сохраняются до завершения
процесса службы; перезапускать её перед экспортом не нужно.

Игровой контроллер работает только в активном раунде выбранного профиля.
На экране результата «Заново?» он останавливается: «Ещё раз» нужно нажать вручную.
Эта версия не добавляет автоматических нажатий по рекламе, меню или перезапуску.
Фактический захват/ввод на Android пока не проверен подключённым устройством.

# Запуск захвата · 0.6.1 Dev

После выбора профиля панель показывает этапы: 1/5 экран, 2/5 служба,
3/5 первый кадр, 4/5 обработка кадров, 5/5 распознана игровая сцена.
Системное разрешение Android остаётся обязательным для каждой новой сессии.

Исправлена гонка первого кадра: готовность получателя публикуется до подключения
ImageReader listener, затем явно считывается уже доступный кадр статичного экрана.
Сессия имеет уникальный идентификатор; результат старого диалога, кадр или ошибка
после STOP не могут запустить новую сессию. Повторный результат не использует
MediaProjection token снова. При пересоздании Activity новый диалог не открывается,
результат ожидается от Android; после гибели процесса требуется новый запуск.

Ожидание выбора ограничено 120 секундами, запуска службы после RESULT_OK — 10,
первого кадра — 3. Возврат из системного выбора без результата также
отслеживается: через 3 секунды после onResume выводится RESULT_MISSING. Затем работает прежняя проверка остановки потока. При ошибке
ввод останавливается; выберите профиль заново для повторной попытки.

«Экспорт задержек» включает раздел CAPTURE STARTUP: последние 40 записей с
монотонным временем, ID сессии, этапом и типом исключения. Журнал находится в RAM
до завершения процесса, экспорт сохраняется пользователем. Снимки, содержимое игры
и токены разрешения в него не записываются. Коды ошибок нормализуются для StageMetrics.

Проверка на телефоне (пока не выполнена в облаке):
1. Открыть активный раунд Маркет Раш, привязать игру и выбрать профиль.
2. Разрешить захват отдельного приложения. Проверить смену этапов и распознавание.
3. Повторить с захватом всего экрана; проверить один ответ на ввод и STOP.
4. Отменить диалог; повторить запуск. Повернуть экран во время выбора, проверить,
   что диалог не дублируется и выдаёт результат либо диагностируемую ошибку.
5. Нажать STOP во время выбора, затем завершить старый диалог: захват не запускается.
6. При ошибке развернуть панель и экспортировать замеры. Экран «Заново?» означает
   завершённый раунд: контроллер не нажимает рекламу и «Ещё раз» автоматически.

Сборка и JVM-проверки не подтверждают поведение MediaProjection на устройстве.
