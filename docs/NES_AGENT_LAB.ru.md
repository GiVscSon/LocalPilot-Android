# LocalPilot NES Agent Lab · первый воспроизводимый цикл обучения

## Зачем отдельная лаборатория

GameLab c десятью нарисованными Canvas-сценами нужен только для тестирования Android-касаний.
Он **не** является точной моделью игр Маркета и не должен считаться завершённым
игровым симулятором.

Для **NES** мы используем другую основу: настоящий эмулятор 6502 CPU + PPU
(JSNES 2.1.0), выполняющий исходный iNES-ROM, с реальным видеобуфером 256×240,
кадрами и кнопками восьмибитного контроллера.

```text
NES ROM → CPU/PPU → кадр RGB → визуальные признаки → состояние агента
                                                   ↓
Обучение Q-learning ← reward от видео ← шаг эмулятора ← кнопка NES
         ↓
checkpoint (ROM SHA256, схема признаков/кнопок, SIM-only)
         ↓
оценка на повторяемых эпизодах без случайного исследования
```

## Что именно сделано в первом эксперимента

В `tools/nes-agent/train.cjs` реализована среда `reset()/step()` поверх
настоящего JSNES. Пока используется **собственный свободный NES homebrew ROM**
из `HomebrewNes.java` и простая проверяемая задача: агент видит на видеокадре
яркий спрайт, двигает его кнопками LEFT/RIGHT и получает награду за визуальное
приближение к правой границе. Ни координата из NES RAM, ни Android ACK не
используются как обучающая метка.

Алгоритм начального эксперимента: tabular Q-learning, 16 дискретных положений
по X, две кнопки LEFT/RIGHT, ограниченное число кадров на действие,
ограниченная длина эпизода. Это **не PPO и не универсальная нейросеть**.
Эксперимент должен доказать жизнеспособность контура, прежде чем усложнять
модель. Код и проверки отклоняют отсутствие распознанного кадра и
неподдерживаемые действия.

## Запуск одними скриптами

Требуются Java 17, Node.js 22, Node-модуль JSNES 2.1.0. Запуск этих команд
уже автоматизирован в GitHub Actions `NES Gym visual reinforcement learning`.
На компьютере можно повторить:

```bash
# После скачивания официального JSNES 2.1.0 и проверки SHA512:
mkdir -p build/nes-gym/classes
javac --release 17 -d build/nes-gym/classes \
  game-lab/src/main/java/org/localpilot/gamelab/HomebrewNes.java \
  tests/ExportHomebrewNes.java
java -cp build/nes-gym/classes ExportHomebrewNes build/nes-gym/training.nes

node tests/nes_training_contract.cjs jsnes.min.js build/nes-gym/training.nes
node tools/nes-agent/train.cjs --core jsnes.min.js \
  --rom build/nes-gym/training.nes --output build/nes-gym/learned --episodes 160
```

Из GitHub Actions загружаются `nes-policy.json` и `nes-episodes.jsonl`.
В контрольной точке должны присутствовать: хеш ROM, схема признаков,
список действий, таблица весов, исход `NES_EMULATED`, результаты обучения
и отдельной оценки. Данные имеют маркировку `NES_SIMULATED` и **не**
авторизуют управление реальной игрой Android.

## Как переходим к другим NES-играм

1. ROM загружается в настоящий эмулятор. Права на ROM/BIOS не передаются
   вместе с проектом; неуполномоченное распространение исключено.
2. Сначала собираем кадры и управление без награды. Размечаем пригодные
   визуальные признаки: игрок, противники, экран смерти, прогресс уровня.
3. Для новой игры создаём отдельный визуальный reward adapter с явными
   проверками и ограничением награды. Не переносим «беги вправо»
   как универсальное решение.
4. Обучение: сначала дискретные действия и проверяемый replay,
   затем DQN/PPO, долговременные эпизоды, и только после проверенной
   связи действия с видео разрешаем более сложную политику.
5. Перенос между NES играми должен иметь отдельные результаты zero-shot
   и fine-tune, откатываемую модель и независимый тестовый набор.

## Что ещё НЕ готово

- Встроенный на телефоне выбор обученного NES checkpoint и автопилот контроллера.
- Полноценное обучение произвольных коммерческих NES игр.
- Воспроизведение всех консолей и DOS: для SEGA и DOS потребуются
  собственные проверенные ядра с тем же контрактом `reset/step/frames/reward`.
- Общая нейросеть, которая сама понимает цели любых игр.
- Доказанный перенос обучения NES в реальные игры Маркета.

`GameLab` остаётся отдельным учебным источником. Запуск настоящих Android
игр по-прежнему регулируется `ActionGate`, `InputPermit`, `TTL`, `STOP`,
UNKNOWN и независимой визуальной проверкой. Никакой симулятор
не снимает эти ограничения.
