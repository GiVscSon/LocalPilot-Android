# LocalPilot 0.8.2 · NES ⇄ ModelLab ⇄ Harness ⇄ обучение

**Интеграция в один APK**, без параллельного владельца ввода.

## Что теперь подключено к выполнению

В единой панели: кнопки «Играть: GGUF до 4 ходов» и «Играть и учиться: Student 16 ходов». В ModelLab находятся те же два маршрута. Они открывают существующий `NesEmulatorActivity`, а не второй эмулятор.

1. JSNES получает проверенную **встроенную** Homebrew NES ROM. Только после подтверждения загрузки и минимум 15 настоящих кадров начинается агент.
2. Для GGUF один и тот же ModelLab runtime использует SHA-привязанную модель. Кадр PNG проходит проверку, затем внутри ModelLab выполняется настоящий GGUF/llama.cpp inference. Модель предлагает строгую кнопку. Результат вычисления сохраняется в `harness-model-execution-v1.log` с latency, SHA модели, числом GPU слоёв и accepted/rejected. Это **не** означает, что ход выполнен.
3. NES `HarnessCoordinator` проверяет ticket, epoch, ROM/frame/hash, TTL и STOP. Единственный JSNES executor исполняет только разрешённую кнопку ровно 16 кадров и получает отдельный ACK. Контрольное изображение, запись перехода и ROM-RAM task evidence проверяются до решения продолжать. Автосерия ограничена **4 ходами**, STOP прекращает всё.
4. Для StudentPolicy реальный CPU студент `StudentPolicyNet` выдаёт action, value и oldLogProb **до исполнения**. Последовательность из **16 подтверждённых on-policy кадровых шагов** допускается `VerifiedReplayFilter`, затем `VerifiedPpoReplayStore` сохраняет атомарный, ограниченный, SHA-256-защищённый `.lpr` файл с 64-dimensional state, next state, вероятностями, решениями и проверенными ROM-RAM rewards.
5. Только после сохранения replay вызывается `LearningCoordinator.prepare()`: выполняется **настоящее обновление весов PPO/GAE** в **candidate** checkpoint. Старые активные веса **не заменяются** без независимой evaluation gate.
6. Console Lab читает тот же каталог GGUF, данные подтверждённых ходов, журнал реальных вызовов модели, on-policy replay и кандидат. ModelLab показывает статус всей цепочки, позволяет импортировать и тестировать модель и запустить тот же сценарий.

Перед новой серией приложение проверяет наличие предыдущего кандидата или его неполной записи и останавливается до игровых действий. Оценка и применение кандидата в Android пока не подключены; существующие файлы сохраняются. Тесты оценки вне приложения не доказывают, что эта функция доступна пользователю.

## Не следует принимать за реализованное

- Никаких автоматически подтверждённых побед в произвольных пользовательских ROM, Dendy, SNES, Game Boy или браузере. Для чужой ROM нет доверенного score/reward provider и кнопок автомагического обучения. Ручной NES-эмулятор и интерфейс импорта ROM остаются.
- GGUF **не** получает градиентного обновления весов от данного цикла. GGUF выполняет инференс/исследование, PPO/GAE обучает отдельную компактную StudentPolicy.
- Даже сохранённый PPO candidate ещё не развёрнут для постоянной игры: `evaluation: NOT_RUN`. «Модель загружена» ≠ «модель использовалась» ≠ «действие подтверждено» ≠ «новые веса оценены» ≠ «игра пройдена».
- Подписанный APK 0.8.2 на основании старого SHA остаётся отдельным артефактом. Это PR-кандидат до GitHub Actions, emulator e2e и запуска на физическом POCO X7 Pro.

## Обязательные проверки и откат

```bash
python3 -m unittest discover -s tests -p test_harness_live_cycle.py -v
java tests/VerifiedPpoReplayStoreVerify.java
java tests/HarnessModelExecutionLogVerify.java
python3 -m unittest discover -s tests -p test_harness_single_panel.py -v
```

Для несинтетического e2e требуется реальная загрузка ROM, серии через JSNES, подтверждения ACK/посткадра и чтения 6502 RAM; затем файловый replay, candidate и независимый тест новой политики. Все ошибки журнала, несовпадения SHA, отсутствие CPU RAM, просроченные ответы GGUF и STOP блокируют последующий ввод.
