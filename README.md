# LocalPilot Android — 0.3.2 Dev

Нативное Android-приложение для встроенных 2048, крестиков-ноликов и «Погаси свет». Агент читает пиксели выделенного поля и отправляет жесты через Accessibility. Поддержка произвольных игр и нейросетевое обучение не реализованы. Модели, сервер и разрешение Internet не нужны.

Исходники импортированы из предоставленного пользователем `LocalPilot_Android_0.3.2_update.zip`. Это отдельный Android-проект; основной LocalPilot для ПК остаётся отдельной задачей в `GiVscSon/my-agent`.

## Что изменено

- «Свернуть / Развернуть» меняет размер панели, сохраняя STOP и текущий режим.
- «STOP и скрыть» останавливает работу и отзывает ввод. Повторное открытие не возобновляет игру автоматически.
- Демо сворачивает панель и ждёт завершения её layout перед первым нажатием.
- Экспорт задержек сохраняет успешные `n` и процентили, дополнительно показывает `attempts`, `errors`, `cancelled`, `last_error`. Ошибка parser больше не выглядит как отсутствие попытки чтения.
- Stop и таймаут освобождают ожидающий захват. Поздний callback старого запроса не может продолжить игру.

Строгие проверки поля, палитры, свежести, окна и разрешения ввода сохранены. Конкретная причина `n=0` на телефоне пользователя ещё не воспроизведена; изменения позволяют увидеть отказавший этап и исправляют подтверждённое поведение панели.

## Установка и проверка на телефоне

Нужен Android 11 или новее. Debug-сборка имеет отдельный пакет **`org.localpilot.android.dev`** и название **LocalPilot Android Dev**. Она устанавливается рядом с прежним приложением, использует отдельные данные и отдельную службу Accessibility. Исходного ключа подписи в архиве нет; установленную версию удалять не требуется.

1. Установите Dev APK и включите именно его службу специальных возможностей.
2. Откройте встроенную тестовую игру. В панели нажмите «Привязать», затем «Разрешить ввод» и подтвердите. Нажмите «Демо ×10»; маленькая панель с STOP должна остаться видимой.
3. Для 2048 или мини-игры откройте её, привяжите окно, выберите точный квадрат поля, затем соответствующий авторежим. Сверьте распознанные клетки перед разрешением ходов. Передвиньте панель, если она перекрывает поле.
4. «Свернуть» сохраняет режим; STOP прекращает будущие действия. Уже отправленный Android жест может завершиться.
5. После ошибки сохраните текст на панели и «Экспорт задержек». Например, `READ n=0 attempts=1 errors=1 last_error=PARSE_REJECTED` указывает на отказ чтения, а не на отсутствие захвата. Экспорт останавливает ввод; снимки в него не входят.

## Сборка и проверки

Нужны JDK 17/21, Android SDK Platform 35 и build-tools 35.0.0. SDK задаётся через `ANDROID_HOME` или локальный `local.properties`, который не коммитится.

```bash
java tests/Verify.java tests/legacy_parity.txt
./gradlew --no-daemon :app:assembleDebug :app:lintDebug :app:assembleDebugAndroidTest
```

В Windows используйте `gradlew.bat`. APK: `app/build/outputs/apk/debug/app-debug.apk`. `build_debug.py --sdk PATH` — дополнительная сборка без Gradle; она также создаёт отдельный Dev-пакет, а её `.build` и ключ не входят в Git. Gradle и standalone используют разные локальные debug-ключи: для последующих обновлений уже установленного Dev сохраняйте выбранный способ сборки и его ключ.

JVM runner проверяет алгоритмы, чтение синтетических пикселей, хранилища и диагностику. Это не проверка Android capture/gesture/UI. Инструментальный runner и его фактический статус описаны в `LOCALPILOT_ANDROID_HANDOFF.md`; успешная компиляция тестового APK не означает выполненный Android-тест.

Упаковка уже собранного APK и переносимых исходников:

```bash
python3 tools/package_release.py
```

В `release` создаются APK, source ZIP, общий ZIP и SHA-256. SDK, кеши, пользовательские данные, `.build` и приватные ключи исключены. Текущие результаты — в `VALIDATION.txt`. Исходная документация архива сохранена в `README.ru.md`; прежние утверждения там относятся к прежним проверкам.
