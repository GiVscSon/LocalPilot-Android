# Полевой аудит LocalPilot · 10.11.2026

## Назначение

Добавлен **строгий офлайн-проверяющий инструмент** для существующего `AuditExport.snapshot` (ZIP v2). Он проверяет метаданные, SHA-256 каждого источника, цепочку `SafeJournal`, размеры и состав архива. Не выполняет Android-жесты, не включает Accessibility, не отправляет данные в сеть, не меняет APK и не подменяет результаты игр.

Этот этап нужен, потому что зелёная матрица эмуляторов **не доказала** работу десяти игр Яндекс Маркета на телефоне и планшете. Доказательства фактического выполнения нельзя приравнивать к ACK или чистой сборке.

## Как получить и проверить журнал

1. В приложении откройте главную страницу → расширенные инструменты → **«Экспорт журнала»**. Android предложит сохранить `localpilot-audit.zip`. Этот вызов останавливает текущий ввод, а не продолжает игру.
2. Перенесите ZIP на компьютер с исходниками проекта (например, в папку `field/`). Архив остаётся локальным.
3. Запустите:

```powershell
python scripts/localpilot.py field-audit --zip "field/localpilot-audit.zip" --output "field/audit-checked.json"
```

Или без оболочки CLI:

```powershell
python scripts/field_audit_gate.py "field/localpilot-audit.zip" --output "field/audit-checked.json"
```

Проверки не требуют Android SDK, ADB, браузера или нейросетей; достаточно Python 3.10+.

## Что отражает отчёт

- `integrity=PASS` означает, что **локальные файлы** соответствуют собственной цепочке хешей и экспорту ZIP. Это обнаруживает случайную порчу, но **не является цифровой подписью устройства**.
- `verified_current` считает только метаданные `VERIFIED_2048`, `VERIFIED_GRID`, `VERIFIED_BUBBLE`, `VERIFIED_ARCADE` из новых сегментов. Legacy-файлы проверяются на целостность, но не суммируются с текущим прогрессом.
- `same_epoch_ack_correlations_not_proof` приблизительно сопоставляет `ANDROID_COMPLETED` с последующими `VERIFIED_*` в том же epoch. В строке `VERIFIED_*` **нет идентификатора жеста**, поэтому связь не доказывает действие.
- `release_ready=false`, `physical_device_verified=false`, `real_market_game_verified=false` выставляются всегда. В аудите **нет идентификатора конкретной игры, доказанного устройства, снимка экрана или идентичности установленной подписи**. Даже тысячи событий не закрывают issue #69 автоматически.

Заранее очищать историю, сбрасывать данные приложения или повторно устанавливать APK для этой проверки нельзя: это разрушает цепочку доказательств. Если ZIP повреждён, инструмент возвращает `INVALID_AUDIT` и ненулевой код завершения. Он не исправляет архив автоматически.

## Испытания

Добавлены девять автоматических отрицательных/положительных контрактов `scripts/test_field_audit_gate.py`. Они включены в существующий `unified verify/all` через `python -m unittest discover -s scripts -p test_*.py`. Нужна новая CI-матрица для **точного SHA** после добавления файлов.

## Что по-прежнему требуется для реальной приёмки

- На настоящем телефоне и планшете записать отдельно десять игровых сценариев: пакеты, профиль, размеры/ROI, timestamps, кадр до/после действия, причину STOP, подтверждённые ходы.
- Сверить журнал с независимыми кадрами, а APK с подписью и commit SHA.
- Не продвигать модели из GameLab/NES в реальное управление, если нет соответствующей подтверждённой визуальной оценки на настоящей игре.
- Сохранить `STOP`, `ActionGate`, `InputPermit`, `TTL`, `UNKNOWN`, protected-skull и правило «Android ACK не доказывает движение».

Итог: скрипт **не закрывает** аппаратную задачу. Он делает архивы диагностически пригодными и предотвращает ложные утверждения о готовности релиза.
