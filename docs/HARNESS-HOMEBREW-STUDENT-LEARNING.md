# Phase 3B · реальное обучение компактной сети из подтверждённых NES-эпизодов

**Status: candidate / sandbox trial only.** Не подтверждает стабильный релиз, полноценный RL на любых ROM или новое обучение GGUF-весов.

## Единая цепочка
1. Встроенная оригинальная `HomebrewNes` запускается в JSNES 2.1.0 под `HarnessCoordinator` STEP_MODE. Только она имеет известный профиль CPU zero-page `$01/$02` и задачу `HOME_BREW_REACH_192_112_V1`.
2. Модель GGUF предлагает разрешённую кнопку, Harness выдаёт одноразовый permit и NES действительно исполняет ровно 16 CPU/PPU кадров. Сначала отпускает кнопку, затем Android проверяет независимый кадр и границы действий.
3. `ConsoleExperienceMemory` сохраняет **проверенные** pre/post X,Y, ROM session epoch, модель ID+SHA, действие, task reward и контрольную сумму. Изменение пикселей само по себе не даёт награду.
4. Явным нажатием на экран Harness Console запускается `HomebrewStudentNetwork.train`. CPU-сеть **7→12 tanh→6** обновляет действительные числовые веса по temporal-difference target, используя только указанный набор. Не заменяет GGUF.
5. Данные разделяются по **целым ROM-сеансам**, а не соседним кадрам. Не менее 12 записей из 3 независимых сеансов, 8 тренировочных и 2 holdout. На holdout считается TD MAE по отношению к нулевой модели. Это **offline проверка на тех же действиях**, а не доказательство, что новая политика выигрывает при самостоятельной игре.
6. Кандидат сохраняется атомарно в хранилище **того же APK**: task/source, train/holdout epochs, веса, SHA256. Недействительная схема, checksum или отличающаяся привязка запрещают infer.
7. Только после отдельной пользовательской команды и успешного offline gate политика `student:<SHA16>` назначается на **один экспериментальный ход**. NES снова отдаёт живой замороженный экран и реальный 6502 X,Y в ModelLab. `HomebrewStudentStore.propose` выбирает допустимую кнопку или `NONE`; реальное нажатие разрешает тот же `HarnessCoordinator` и журнал подтверждает outcome. У студента **нет собственного второго контроллера**.

## Состояния, которые нельзя смешивать
`COLLECTED` ≠ `TRAINING_WEIGHTS_CHANGED` ≠ `OFFLINE_TD_PASS` ≠ `STUDENT_BOUND` ≠ `REAL_NES_ACTION_VERIFIED` ≠ `ONLINE_GOAL_REACHED` ≠ `RELEASE_READY`.

Никакая сеть не продвигается автоматически в стабильный агент. Действующий режим одного шага позволяет собирать независимые on-policy наблюдения. Системные Android жесты недоступны модели.

## Проверки
- JVM: реальные градиентные изменения 7×12×6, запрет подделанной награды, session holdout, finite weights, недостаток данных → отказ.
- Source contract: единый snapshot CPU → ModelLab → student infer → строгое NES MOVE, отсутствие dispatchGesture.
- CI: All-in-One ARM64 + x86 emulator navigation, Whole System JSNES NROM, API30/35/36 матрица. Физический POCO X7 Pro и CPU/Vulkan бенчмарк отдельно.

## Открыто
Для публичных ROM нет verified reward/task adapter. Нет подтверждённой on-policy победы, автоматической многошаговой игре, независимой online A/B оценки, успешной GPU-загрузки весов или переноса модели между ядрами. Оценка и promotion отдельным последующим этапом, после достаточно реальных NES-эпизодов.
