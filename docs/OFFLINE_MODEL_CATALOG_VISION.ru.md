# LocalPilot Android: предзагруженный выбор моделей и ручная диагностика кадров

## Цель
Для POCO X7 Pro с 12 ГБ ОЗУ подготовлена отдельная **экспериментальная** сборка, где четыре локальные модели хранятся **непосредственно в APK**. Компактная сборка со встроенной GGUF содержит только MNN-Pocket; обычная Dev-сборка без GGUF использует внешний Termux-сервер. Никаких сетевых загрузок моделей в установленном APK.

| Выбор в UI | Файлы внутри Offline Catalog APK | Задача |
| --- | --- | --- |
| MNN-Pocket 0.3B | MNN-Pocket-0.3B-Instruct-Q4_1.gguf (~192 МБ) | запасная модель |
| Qwen3.5-0.8B | Qwen3.5-0.8B-Q4_0.gguf (~563 МБ) | стратегия и объяснения |
| LFM2.5-350M | LFM2.5-350M-Q4_0.gguf (~219 МБ) | короткие ответы |
| LFM2.5-VL-450M | LFM2.5-VL-450M-Q4_0.gguf (~219 МБ) + mmproj-LFM2.5-VL-450m-Q8_0.gguf (~103 МБ) | фотографии/скриншоты вручную |

**Итого веса ~1,30 ГБ**, APK ещё содержит игровые файлы и native library. На первом использовании веса выбранной модели проверяются по SHA-256 и распаковываются в личное хранилище приложения, поэтому нужно свободное место с запасом. Выбор хранится в приватных настройках; одновременно активна только одна native-модель.

## Как устроено
1. Экран «Локальное ИИ-ядро» показывает каталог и даёт выбрать модель. Если установлен компактный APK, неподготовленные модели честно обозначаются «не включена в APK», выбрать их нельзя.
2. Стратегический анализ выполняется асинхронно, по профилю игры и белому списку анонимизированных метрик. **CPU остаётся единственным исполнителем всех игровых жестов**; MNN/Qwen/LFM не меняют ActionGate, STOP, TTL, InputPermit, геометрию ROI или награду.
3. Фото/скриншот выбирается **вручную** системным Android-пикером. Из выбранного изображения извлекаются только RGB-пиксели, уменьшаемые до максимума 640×640. EXIF и путь файла модели не отправляются. Фотография существует только в памяти приложения и поступает в нативный `libmtmd` с проверенным проектором LFM2.5-VL. Нет сетевых запросов, автоматического сбора экрана или прямого ввода от модели.
4. Вывод VLM носит **диагностический** характер, не служит разрешением на игровой ход и не заменяет детекторы CV. Требуется реальный тест изображения, а не текстовая имитация.

## Сборка и проверка
- Отдельный workflow: `.github/workflows/offline-model-catalog.yml`, опция `-PbundleLocalModelCatalog=true`.
- Скрипт `tools/bundle_optional_models.py` загружает только конкретные файлы из неизменяемых Git/HF ревизий, сверяет размеры и SHA-256 с LFS, генерирует подписанный вместе с APK JSON манифест, сохраняет отчёт для проверки.
- **Ограничение**: текущие дополнительные ревизии фиксируются на время CI-запуска, но не записаны в исходный version-lock; до стабильного релиза следует закрепить точные SHA и проверить лицензионные условия (включая LFM1.0).
- Native JNI должен пройти реальную генерацию на MNN, Qwen, LFM и на RGB-снимке с LFM2.5-VL + mmproj. Затем в CI проверяются подпись APK и содержимое; физические POCO X7 Pro / планшетные тесты остаются отдельным этапом.

Это устраняет столкновение между вариантами сборок на телефоне.\n\nОтладочный ключ GitHub Actions может отличаться между **повторными запусками одного варианта**, поэтому этот кандидат ещё не имеет стабильной обновляемой подписи. Для настоящего релиза нужен постоянный защищённый signing key.
