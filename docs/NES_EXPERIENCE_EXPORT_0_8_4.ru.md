# Экспорт и продолжение NES-опыта · кандидат0.8.4/code56

База main1413aadc, проверенный кандидат0.8.3. Прежняя версия сохранена в
archive/main-before-experience-export-20261115. Старые зелёные проверки не
относятся к этому новому APK.

Harness Console → Эпизоды → «Архивировать опыт · освободить рабочий журнал».
Операция доступна только при свободном Harness. MaintenanceLease запрещает
новые ручные/модельные действия, наблюдения и PPO-эпизоды, пока архив записывается.
Монитор контроллера не удерживается на дисковом IO: STOP остаётся немедленным.
Завершение maintenance не выдаёт разрешений ввода и не возвращает старых tickets.

NesExperienceArchive проверяет цепочку RAM-журнала и каждый PPO replay, записывает
приватный ZIP с manifest SHA256/размерами, выполняет fsync и readback, затем
атомарно публикует архив. Только после этого удаляются побайтно совпавшие рабочие
записи. Сохранение CPU/PPU, модели, кандидаты и старый визуальный журнал не меняются.
Если процесс прервётся во время освобождения, часть активных записей может
дублироваться в архиве, но все удалённые байты уже находятся в сохранённом ZIP.
Архивы не используются как новый on-policy опыт и не меняют происхождение данных.

До8 локальных архивов, каждый до6MiB, исходные пределы256 RAM-строк/64 replay-серий
сохранены. При заполнении требуется экспорт. Файл выбирается через Android
Storage Access Framework: приложение записывает ZIP, закрывает, перечитывает
назначение, сравнивает размер и SHA256 с локальным архивом. Лишь после совпадения
освобождается локальная копия. Отмена выбора, отказ записи, отсутствие readback
и неверная контрольная сумма сохраняют локальный архив. Сетевой отправки нет.
Если выбран сторонний файловый провайдер, сохранением назначения управляет он.

Повреждённые/неожиданные файлы и symlink отвергаются с сохранением данных.
Оставшийся после аварии неполный .pending файл требует диагностики: его нельзя
удалять как заведомо ненужный. Автоматическое восстановление такого случая пока
не реализовано. Универсального импорта архивов в обучение также нет.

Локально:20 JVM persistence/failure assertions,83 Harness checks,5 Python негативных
проверок архива,7 single-panel и5 live-cycle PASS. Android Java/AndroidTest compile
и Lint PASS. Это синтетические контракты, не результаты физических игр.
В существующую API30/35/36×phone/tablet матрицу добавлен фактический UI-путь:
архивировать→сверить все оригинальные байты→отмена экспорта→сохранение через SAF→
SHA файла Downloads→продолжить CPU/PPU с сохранённого прогресса и собрать новый опыт.
Новый runtime CI пока не подтверждён. Физическая приёмка NOT_RUN, release_ready=false.

Независимый экзамен и продвижение нового on-device PPO-кандидата остаются
следующим этапом; эта работа не заявляет улучшения весов или автоигру произвольных ROM.
