# LocalPilot Android — 0.3.3 Dev

Нативное Android-приложение для встроенных 2048, крестиков-ноликов и «Погаси свет». Агент определяет поле, читает его пиксели и отправляет жесты через Accessibility. Версия 0.3.3-dev имеет `versionCode=7`. Модели, сервер и разрешение Internet не нужны.

Исходники импортированы из предоставленного пользователем `LocalPilot_Android_0.3.2_update.zip`. Это отдельный Android-проект; основной LocalPilot для ПК остаётся отдельной задачей в `GiVscSon/my-agent`.

## Что изменено

- **«Автополе»** привязывает открытое окно и определяет поле. Для встроенных 2048, крестиков и Lights Out используются реальные экранные границы Accessibility-узла поля; значения клеток по-прежнему читаются из снимка, а не из массива игры.
- В сторонней игре автопоиск ограничен стандартной палитрой 2048. Поиск выполняется в ограниченном worker, прекращается по Stop/таймауту и не выбирает неоднозначное поле. Другим палитрам и механикам нужен отдельный профиль.
- Панель при необходимости перемещается вне найденного поля. Перед ходами остаётся подтверждение распознанной матрицы; обнаружение поля само по себе ввод не разрешает.
- Добавлен выбор установленных игр с поиском по названию или пакету. Если Android не назначил игре категорию, её можно найти через «Все приложения». Выбор открывает приложение и подготавливает привязку к его устойчивому окну с выключенным вводом.
- Элементы управления помещены в прокручиваемую часть панели. Ручные действия недоступны без привязки и подтверждённого ввода; повторные нажатия после Stop больше не создают искусственные попытки отправки жеста.
- «Свернуть / Развернуть» меняет размер панели, сохраняя STOP и текущий режим.
- «STOP и скрыть» останавливает работу и отзывает ввод. Повторное открытие не возобновляет игру автоматически.
- Демо сворачивает панель и ждёт завершения её layout перед первым нажатием.
- Диагностика различает отсутствие привязки `NOT_BOUND`, изменение окна/сеанса и истечение `TICKET_EXPIRED`, а также другие конкретные причины gate. Все отказы больше не объединяются под `STALE_TICKET`.
- Экспорт задержек сохраняет успешные `n` и процентили, а также `attempts`, `errors`, `cancelled`, `last_error`. Отдельная строка `error_counts` содержит счётчики по кодам: до 32 кодов на этап, остальные отказы учитывает `error_overflow`. `last_error` означает только последнюю ошибку.
- Stop и таймаут освобождают ожидающий захват. Поздний callback старого запроса не может продолжить игру.

Строгие проверки поля, палитры, свежести, окна и разрешения ввода сохранены. Doodle Jump, раннеры и произвольные игры пока не имеют автоматических профилей; для них доступны выбор приложения и ручные касания/свайпы. Нейросетевое обучение не реализовано; сохранённые игровые примеры не являются обученной политикой.

## Что подтверждают полученные журналы

Пользовательские экспорты прежнего APK содержат 32 завершённых Android ACK и 20 последовательных проверенных переходов 2048. Полный раунд из 20 ходов согласуется с 44 успешными чтениями, 20 решениями политики и накопленной наградой 148. Это подтверждает работу данного ограниченного раунда по предоставленным данным, но не проверку нового APK или всех режимов.

В прежних метриках есть четыре отказа чтения и 186 ошибок на этапе отправки при последнем коде `STALE_TICKET`. Последний код не устанавливает причины всех 186 ошибок: старый экспорт не сохранял их распределение. Новый экспорт добавляет гистограммы, чтобы последующие случаи можно было различить. Причина каждого прежнего отказа по этим файлам не восстановлена.

## Установка и проверка на телефоне

Нужен Android 11 или новее. Debug-сборка имеет отдельный пакет **`org.localpilot.android.dev`** и название **LocalPilot Android Dev**. Она устанавливается рядом с прежним приложением, использует отдельные данные и отдельную службу Accessibility. Исходного ключа подписи в архиве нет; установленную версию удалять не требуется.

1. Установите Dev APK и включите именно его службу специальных возможностей. Для обновления уже установленного Dev нужен APK с тем же ключом подписи; оригинальное приложение удалять не требуется.
2. Откройте встроенную 2048, крестики-нолики или «Погаси свет» и нажмите «Автополе» в панели. Кнопка сама подготавливает привязку и поле. Сверьте всю матрицу с игрой и только затем подтвердите ввод.
3. Для сторонней игры откройте «Выбрать установленную игру» в главном окне или «Выбрать игру» в панели. При необходимости переключите список на «Все приложения». Для совместимой стандартной 2048 попробуйте «Автополе». Если автопоиск не подтвердил поле, используйте «Привязать → Выбрать поле → Авто2048»; неподдерживаемым палитрам или играм нужен отдельный профиль.
4. Для проверки ручного ввода откройте встроенную тестовую игру, нажмите «Привязать», затем «Разрешить ввод» и подтвердите. Нажмите «Демо ×10»; маленькая панель с STOP должна остаться видимой.
5. «Свернуть» сохраняет режим; STOP прекращает будущие действия. Уже отправленный Android жест может завершиться.
6. После ошибки сохраните текст на панели и «Экспорт задержек», включая строки `error_counts`. Например, `READ n=0 attempts=1 errors=1 last_error=PARSE_REJECTED` указывает на отказ чтения, а не на отсутствие захвата. Экспорт останавливает ввод; снимки в него не входят.

## Сборка и проверки

Нужны JDK 17/21, Android SDK Platform 35 и build-tools 35.0.0. SDK задаётся через `ANDROID_HOME` или локальный `local.properties`, который не коммитится.

```bash
java tests/Verify.java tests/legacy_parity.txt
./gradlew --no-daemon :app:assembleDebug :app:lintDebug :app:assembleDebugAndroidTest
```

В Windows используйте `gradlew.bat`. APK: `app/build/outputs/apk/debug/app-debug.apk`. `build_debug.py --sdk PATH` — дополнительная сборка без Gradle; она также создаёт отдельный Dev-пакет, а её `.build` и ключ не входят в Git. Gradle и standalone используют разные локальные debug-ключи: для последующих обновлений уже установленного Dev сохраняйте выбранный способ сборки и его ключ.

Текущий JVM runner прошёл **9224 проверочных утверждения**: алгоритмы, синтетические пиксели, выбор геометрии поля, хранилища и диагностика. Это не 9224 Android-теста и не проверка захвата/жестов нового APK на телефоне. Инструментальный runner компилируется, но его Android-запуск не выполнен. Финальный результат сборки и lint фиксируется в `VALIDATION.txt` и `LOCALPILOT_ANDROID_HANDOFF.md`; успешная компиляция не означает device acceptance. Прежняя попытка в программном эмуляторе остановилась на перезапуске Android framework до запуска приложения.

Упаковка уже собранного APK и переносимых исходников:

```bash
python3 tools/package_release.py
```

В `release` создаются APK, source ZIP, общий ZIP и SHA-256. SDK, кеши, пользовательские данные, `.build` и приватные ключи исключены. Текущие результаты — в `VALIDATION.txt`. Исходная документация архива сохранена в `README.ru.md`; прежние утверждения там относятся к прежним проверкам.
