## 2. Воспроизводимые наблюдения пользователя (скриншоты, не автоматический тест)
**Match World, 7×7, 27.10.2026**
- 11:15: CAPTURE/PANEL_COVERS_ROI, кадры=2, READ=2, решения=0, ввод=0, ACK=0.
- 11:17: CAPTURE/PANEL_COVERS_ROI, кадры=99, READ=99, решения=0, ввод=0, ACK=0. Панель закрывала середину сетки.
- 11:20: кадры=18, READ=18, решения=3, ввод=3, ACK=3, затем «Нет подтверждённого изменения поля · ввод приостановлен». Экран показывал 27 ходов и 10 красных объектов; ранее 32 хода и 32 красных, но сравнение разных скриншотов **не позволяет доказать** конкретный прогресс этих трёх жестов.
- Диагноз: есть **две разные** блокировки (перекрытие ROI и отсутствующее подтверждение результата). Фраза «останавливается после трёх шагов» НЕ доказывает жёсткий счётчик попыток.
- Реальный код `GridPuzzleSession.java`: FRESH_MS=300, STABLE_MS=80, SETTLE_MS=180, стандартный responseTimeoutMs=2500. После ACK нужны два свежих устойчивых кадра с подтверждённым изменением распознанной сетки. Если до дедлайна доказательство не получено, статус PAUSED, автоматический повтор запрещён.
- Реальный код `PilotService.java`: на старте grid использует `movePanelAway(boardRoi)`, а при screenshot отклоняет перекрытие `PANEL_COVERS_ROI`. Нужно проверить реальную геометрию и поведение компактизации на телефоне, не отключать gate.
- Предположительные причины без установления корня: ошибочная область, неподходящий профиль SWAP_MATCH3, неправильная трансформация координат, короткий/неправильный drag, анимация/поздний свежий кадр, неизвестные особые клетки/фон.

**Карканоид / блоки, 27.10.2026**
- Виден захват READ1630, шар, нижняя подвижная корзина, блоки. Пользователь сообщает: блоки опускаются; если их не уничтожить до невидимой линии приблизительно на высоте платформы, игра проиграна. Агент этого дедлайна не учитывает.
- Точный уровень линии, скорость движения и триггер падения (время/ход/раунд) НЕ установлены. Нельзя жёстко зашивать координаты по одному снимку.
- Требуется отслеживание каждого блока во времени, оценка оставшихся секунд/шагов, возможность попадания, число попаданий до разрушения, прогноз мяча и оценка риска потери мяча. Самая опасная достижимая цель приоритетнее очков, но спасение мяча приоритетнее безнадёжной атаки.
- Проверить после удара исчезновение именно целевого блока, а не только ACK.

**Другие записи:** в видео с прыжком было системное разрешение захвата; в видео с пузырями была ручная настройка области. Одно наличие диалога/меню не доказывает игровой прогресс.

## 3. Выводы статического аудита механик 10 игр
| Игра | Подтверждённый код / ограничения | Следующая проверка |
| --- | --- | --- |
| 2048 | Board2048/Color2048Reader/Verified2048, только подтверждённые изменения | Отличать успешный свайп от нового игрового состояния |
| Шипучка | BubbleVision/Policy/Session; четыре обычных цвета, прямой путь/один рикошет; 0.7.33 допускает одиночный остаточный шар при ранее известной геометрии | Реальный post-ACK результат; бомба/радуга/несколько рикошетов НЕ доказаны |
| Прыгун Ари | JumperState.horizontalDistance УЖЕ считает минимальный wrap; JumperPolicy использует его | Не дублировать wrap, проверить телеметрию edge-crossing и физику прыжка |
| Мэтч Ворлд | GridPuzzlePolicy.SWAP_MATCH3 для 7×7, ортогональный соседний обмен; не все special объекты поддержаны | Причина PANEL_COVERS_ROI, stale/unchanged после ACK |
| Нащупай ход | Для описанного 6×6 в справочнике выбран ОБМЕН соседей с защитой черепов; есть общий режим прямой TRACE_LINE, но механика конкретной игры требует проверки | Не внедрять DFS с 8 соседями без реального доказательства, что игра принимает цепочки |
| Карканоид | ArcadePolicy/Controller/ Vision для платформы и мяча | Дополнить трекингом опускающихся блоков и линией поражения (после подтверждения механики) |
| Маркет Раш | Arcade TRAFFIC, полосы и препятствия | Реальная смена полосы + post-ACK outcome |
| Гошан, вперёд | FLAPPY и ограниченный прогноз импульса | Проверка счётчика и предотвращения столкновения, не по ACK |
| Котобашня | отдельного подтверждённого адаптера нет | Stomp Attack только после проверки «врага можно побеждать сверху» на конкретной игре |
| Гексон | отдельного подтверждённого HexaSort нет | Построить модель 6 соседей/3 доступных стеков только после реальных кадров и проверки правил |

Факты из присланного стороннего технического гайда о WRAP_FARM_MODE, атаке врагов, диагональной связности, бомбе и HexaSort = **гипотезы/идеи**, не готовые функции. Не переписывать рабочую логику по непроверенному руководству.

## 4. Матрица P0 и критерии приёмки
| Проверка | Уже есть? | Обязательный следующий эксперимент |
| --- | --- | --- |
| Захват свежего кадра и правильного окна | Частичные пользовательские скриншоты/прежние тесты | frameId+session+generation+windowId+ROI+timestamp, stale-frame/rotation/Stop negative |
| Перекрытие ROI панелью | Воспроизведено пользователем | вычислить пересечение и разместить STOP вне ROI либо безопасно приостановить; тест на 7×7/разных DPI |
| Классификация Match World | Прототип/синтетика | сравнить 2 последовательных кадра и карту 49 клеток, измерить уверенность и special-mask |
| Валидность swap | Имеется policy | offline рассчитать легальный обмен и фактические touch start/end, не делать невалидные действия |
| Ввод/ACK | 3/3 по скриншоту | различить gesture dispatched / Android ACK / fresh observed game outcome |
| Верификация результата | Пауза после непроверенного | причины ACK_MISSING, FRAME_STALE, INCOMPLETE, ANIMATION_PENDING, BOARD_UNCHANGED, UNSTABLE, TIMEOUT; ровно 2 post-ACK устойчивых кадра |
| Защита от касаний и данных | реализованные ActionGate/STOP по исходникам | 0 повторов из pending без подтверждения, stale/смена окна/stop не нажимают ничего |
| E2E на настоящем Android | Нет для версии 0.7.33 | один проверенный swap, затем 5 последовательных подтверждённых ходов; экспорт ограниченной трассы без пользовательских фото |
| Карканоид threat-priority | Требование пользователя | серия кадров для калибровки линии и модели падения; offline baseline vs threat-policy, затем только shadow |

Изменения кода выполнять **только** в отдельной ветке на основе реального head `sync/localpilot-android-0711` после резервной копии и smoke-check. Не менять ветку `main` как базу, не force push, не переустанавливать APK с потерей checkpoints, не заменять dev signer, не выгружать приватные видеокадры/логи. Единственный executor; no ACK-as-reward; сохранение data и безопасный Stop.
