# Termux/Linux на Android: применение к LocalPilot

Проверены официальные README Termux,PRoot-Distro,Termux:API,Termux:X11,termux-packages и инструкция llama.cpp для Android. Это исследование документации,не установка на телефон. Текущий APK0.7.6 к Termux не подключён.

## Какие варианты существуют

| Вариант | Что получается | Решение для LocalPilot |
|---|---|---|
| Обычный Termux | Терминал и пакеты,собранные для Android; Bash,Python,Git,Clang,локальные серверы;root не нужен | Первый выбор для дополнительного вычислительного модуля |
| Termux + proot-distro | Linux userland Debian/Ubuntu и других дистрибутивов поверх ядра Android;не требует root | Дополнение для совместимости с обычными Linux-программами |
| Termux:X11 | Графические Linux-приложения с отдельным Android-приложением X11 и пакетом Termux | Для нашей фоновой обработки не требуется;можно добавить для ручной лаборатории |
| chroot | Другая организация Linux-окружения с настоящими привилегиями root | Не требуется для предложенной архитектуры |

PRoot не устанавливает другое ядро и не предоставляет настоящие root-права Android. Есть накладные расходы на перехват системных вызовов,особенно при работе с файлами. Полноценный systemd и функции,cвязанные с cgroups/namespaces/модулями ядра,обычно недоступны. Отдельный серверный процесс запускать можно,но Android может завершить фоновые процессы.

Нюанс актуальной документации:современный proot-distro умеет загружать Docker/OCI-образы и собирать часть Dockerfile без Docker daemon. Это не означает,что на телефоне появляется полноценный Docker Engine или обычная изоляция Linux-контейнеров.

## Что полезно конкретно нам

- Python-инструменты для извлечения кадров из видеозаписей,разметки примеров и повторяемых проверок распознавания.
- Локальное хранилище образцов/метрик и обработка данных без отправки снимков в сеть.
- Дополнительный HTTP-сервис для редкой классификации неизвестной сцены или анализа отчёта. Для быстрого аркадного управления предпочтителен нативный детектор в APK.
- llama.cpp официально описывает сборку CLI в Termux. Модель надо отдельно подобрать под память/процессор телефона. Текстовая GGUF-модель не начинает видеть изображения только из-за запуска в Termux;для зрения нужна поддерживаемая мультимодальная модель и соответствующая конфигурация. Работоспособность GPU/Vulkan и скорость на нашем устройстве не проверены.
- Linux через PRoot полезен,если необходима glibc-зависимость или Debian/Ubuntu-пакет. Обычные Linux wheels дляPython не следует считать совместимыми с нативным Termux автоматически;поддержка OpenCV/PyTorch и конкретной модели проверяется отдельно.

## Что Termux не исправляет сам

Termux/PRoot работают с правами своего Android-приложения. Они не дают автоматический доступ к экрану другой игры,внедрение касаний,обход системного согласия MediaProjection или доступ ко всем закрытым каталогам приложений. Termux:API предоставляет определённые Android API,но не превращает приложение в универсальный root-контроллер. Запуск shell-команды input из обычного приложения не равнозначен запуску от ADB-shell/root.

Отдельный путь для разработки — ADB через беспроводную отладку с явным сопряжением,если его поддерживает телефон. Это другая схема доступа,не автоматическое следствие установки Linux. Для пользовательской работы основным механизмом остаётся APK с AccessibilityService и MediaProjection.

## Предложенная схема

APK получает разрешённый кадр,выбирает окно/область и выполняет жесты. Встроенный быстрый контроллер ведёт аркаду. При необходимости APK передаёт уменьшенную область локальному сервису Termux для дополнительного анализа и получает структурированный ответ. После возврата ответа APK заново проверяет сессию,возраст кадра,приложение/окно/область и допустимость действия. Запоздалый ответ не становится новым касанием.

Медленную модель разумно использовать для меню/объяснения неизвестной сцены/подбора профиля,а не как единственный контроллер динамической аркады. Задержку,память и энергопотребление нужно измерить на телефоне. При недоступности Termux APK продолжает самостоятельное распознавание или остаётся в режиме наблюдения.

Сервис должен слушать127.0.0.1,а не0.0.0.0;для общения нужны проверка версии протокола,ограничения размера/тайм-аутов и аутентификация. Localhost доступен и другим локальным приложениям,поэтому он не заменяет аутентификацию. В существующем AndroidManifest LocalPilot usesCleartextTraffic=false:HTTP-интеграция потребует отдельного узкого разрешения дляloopback либо другого транспорта. Такой сетевой мост в этой задаче не реализовывался;ослабление общей сетевой политики APK не выполнялось.

## Минимальная ручная установка

Установить Termux из официального источника: [F-Droid](https://f-droid.org/packages/com.termux/) или [релизы Termux](https://github.com/termux/termux-app/releases). Если уже установлен Termux/его дополнения,не удалять их и не смешивать APK разных источников без резервной копии:подписи должны быть совместимы. У Google Play есть отдельная экспериментальная ветка;не следует считать её автоматически идентичной другим сборкам.

В консоли Termux:

```sh
pkg update
pkg install python git clang cmake proot-distro
proot-distro --help
```

Для Linux-дистрибутива команды зависят от установленной версии proot-distro. В актуальном README сOCI-образами:

```sh
proot-distro install ubuntu:24.04
proot-distro login ubuntu
```

В более старых версиях с каталогом дистрибутивов:

```sh
proot-distro list
proot-distro install ubuntu
proot-distro login ubuntu
```

Следует использовать только подходящий установленной версии вариант;не устанавливать оба и не выполнять reset/remove существующего окружения. ВнутриUbuntu:

```sh
apt update
apt install python3 python3-venv git
```

Это команды для телефона,здесь они не исполнялись. GUI/Docker/root для первого этапа не нужны. Перед тяжёлыми пакетами и моделями проверитьAndroid,ABI,доступнуюRAM/диск и поведение фоновых процессов;модель телефона и актуальные характеристики из этой сессии неизвестны.
