# Live-game learning: 2048 + Шипучка (кандидат 27.10.2026)

## Цель пользователя
Не копить опыт только в тестовом демо: проверенный результат настоящей игры должен влиять на последующие разрешённые ходы. Интеграция в Android, НЕ перенос и НЕ обучение JEV/PC/Ollama/нейросети.

## Реализовано в отдельной ветке
- `LiveGameLearning`: компактные ограниченные счётчики подтверждений и качества, формат `v1`. Не хранит пиксели или историю экранов. Модели 2048 и Bubble несовместимы по формату, направлению и выбору действий. Данные разделены ещё и `profileChoiceKey(target)` (пакет/слот), стандартная и цветная 2048 отдельно.
- **2048**: `Board2048.choose(IntToDoubleFunction)` сохраняет все прежние условия допустимости хода и добавляет небольшой (не более 3 баллов) бонус к уже разрешённым направлениям. `PilotService.round2048` записывает качество только после `Board2048.verifies(...)` на фактическом устойчивом post-ACK кадре и `SafeJournal.VERIFIED_2048`; ACK и необработанный кадр НЕ являются наградой.
- **Шипучка**: `BubblePolicy.choose(..., ToDoubleFunction<Shot>)` ранжирует только те геометрически безопасные траектории, которые уже прошли полный исходный фильтр (не более 6 баллов на фоне >=100 баллов за удаление). `BubbleSession.Status.VERIFIED` фиксирует качество только при точном совпадении предсказанного и наблюдаемого поля после ACK; `PAUSED` с ACK регистрируется как `unconfirmed`, НЕ как проигрыш. По окончании/STOP/неудавшемся dispatch привязка к ожидаемой траектории стирается.
- Модель подгружается при следующем старте игры и живёт в отдельных Android SharedPreferences `live-game-learning` с ключом `profileChoiceKey(target)+.2048/.color2048/.bubble.verified-live-v1`. Битая сохранённая модель не перезаписывается: обучение для этой игры отключается, игровая стратегия откатывается к безопасной базе.
- В `uiStats` и экспортной диагностике есть раздельные количества `verified` и `unconfirmed`; прежние файлы `ExperienceStore`, `ArcadeLearningStore` и `GridOnlineLearning` не затронуты.

## Границы/неподтверждённое
- Это **инкрементальное табличное обучение качеству направления/траектории**, не PPO, не новая локальная нейросеть и не утверждение о победах в Яндекс Маркете.
- Исторические записи `ExperienceStore` не импортируются автоматически в новую модель: импортированные записи сами по себе не являются подтверждёнными живыми наблюдениями, а формат хранит другие профили.
- Спецшары, нераспознанные клетки, неизвестная геометрия и обратная фаза рядов остаются в read-only/STOP по существующей логике. Если исчезает фокус, stale ROI, TTL/lease нарушен или не подтверждён игровой отклик, новые жесты не разрешаются.
- Физический POCO X7 Pro: **NOT RUN**. Независимой оценки улучшения процента побед: **NOT RUN**. APK с новой функцией НЕ выпускать как stable до завершения CI.

## Матрица проверки
- `java tests/Verify.java tests/legacy_parity.txt`: включает `LiveGameLearningTest`, проверку влияния на выбор реального 2048, восстановление после рестарта, отказ при испорченных счётчиках, насыщение 20k наблюдений, отсутствие заимствования опыта другой игры.
- `java tests/BubbleVerify.java`: проверяет вызов функции ранжирования только для безопасных рассчитанных кандидатов, сохранение изначальной безопасной траектории при нулевом опыте.
- `gradle :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug`, JVM и `Android device acceptance` API30/35/36 в GitHub Actions (результаты смотреть по актуальному SHA, не по старой ветке).
- Полевой тест на настоящем телефоне: сбросить только тестовый слот (без удаления пользовательских данных); выполнить 1, затем 5 пост-ACK подтверждённых ходов в каждом профиле и проверить, что после перезапуска значения модели сохранились и безопасные действия учитывают бонус. Отдельно подтвердить, что 3 ACK без визуального результата НЕ дают положительных примеров.
