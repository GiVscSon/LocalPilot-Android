# Почему LocalPilot ещё не подписан · 12.11.2026

Проверены GitHub API, фактические workflow runs и локальная среда. Проверка правил workflow и создание подписанного APK — разные операции.

## Подтверждённые причины

1. **Подписывающая операция ни разу не запускалась.** У workflows `416250440` и `415667812` число `workflow_dispatch` runs равно нулю. В PR #106 run `43257675945`, PR #107 run `43259615303` задания policy прошли, а `signed-candidate` получили SKIPPED: для pull_request условие разрешает только проверку правил.
2. **Ручной dispatcher отсутствует в default branch `main`.** Contents API для `.github/workflows/localpilot-unified-release-dispatch.yml?ref=main` возвращает 404, а README из той же ветки читается. PR #106 остаётся открытым. Регистрация workflow как active не подтверждает наличие файла в default branch.
3. **Защищённое окружение не создано.** `GET /repos/GiVscSon/LocalPilot-Android/environments` вернул HTTP 200, `total_count=0`. Это положительная проверка отсутствия окружений, а не вывод по неоднозначному 404 secrets.
4. **Подключению GitHub недостаёт прав для настройки подписи.** Попытка создать `android-signing` с обязательным одобрением владельца через PUT отклонена HTTP 403 `Resource not accessible by integration`. Чтение repository secrets тоже даёт 403; требуется соответствующее разрешение GitHub App. Repository-role `admin=true` не расширяет разрешения приложения. Существование/отсутствие repository secrets таким ответом не устанавливается; значения секретов не запрашивались.
5. **Доступного постоянного release-ключа не обнаружено.** В доступных каталогах проекта, временных файлов и профиля пользователя найден только стандартный `.android/debug.keystore`, сертификат `CN=Android Debug`. Ни его наличие, ни новый произвольный ключ не доказывают совместимость с установленным `org.localpilot.android`. Физических ADB-устройств нет; сертификат установленного приложения не проверен.

## Исправленные ошибки кода

PR #107 встраивает фактический checkout SHA в APK, а signed release gate отклоняет несовпадение с запрошенным SHA. При аудите найден дополнительный конфликт: dispatcher работает из `main`, но собирает `inputs.source_sha`; `GITHUB_SHA` события остаётся SHA workflow, поэтому прямое сравнение с checkout ошибочно.

Исправление использует отдельный строгий `LOCALPILOT_BUILD_SOURCE_SHA`, сверенный с настоящим git HEAD. При отсутствии явного pin обычный CI проверяется по `GITHUB_SHA`. Некорректный, пустой и чужой pin отклоняются. Парная правка PR #106 передаёт выбранный SHA в шаг сборки. Встроенные метаданные всегда берутся из checkout, не из произвольной входной строки.

Также policy PR #106 проверял обязательные строки во всём файле, включая собственный список этих строк. Теперь проверяется именно signed-candidate; отрицательные тесты удаляют Environment, source pin и dispatch trigger из настоящего workflow.

Проверки: 9 signing-gate tests PASS; 6 реальных Gradle-кейсов pin/fallback PASS; 4 workflow-policy tests PASS. Повторить Gradle-проверки с настроенными JAVA_HOME/ANDROID_HOME можно командой `python3 tools/check_signing_source_pin.py`. Это не создание подписи и не сборка полного релизного APK.

## Остальные ограничения

На исходном SHA PR #107 `c138168` All-in-One, Embedded, Unified, Catalog, Whole-System и Build прошли; API30/36 прошли. API35 job `131327126950` run `43259615246` упал до игровых сценариев: `PilotService is not connected`, checks и interaction trace пусты. Состояние настроек в момент ожидания не записано, поэтому точная причина этого подключения не доказана. Это отдельная ошибка стенда, не ошибка ключа. После изменения исходников результаты заново проверяются CI.

Подпись пока не изолирована от сборки выбранных исходников в отдельный runner. SHA обеспечивает идентичность, а не доверие к коду. До подключения настоящего ключа необходимы реальное protected approval и проверка границы доверия build/sign; утечек этим аудитом не установлено. Отпечаток сертификата и совместимость обновления должны проверяться отдельно. VersionCode 53 не является увеличением относительно установленной 53, если на устройстве именно она; без устройства это условие не проверено.

Для завершения нужны доступные в GitHub разрешения на защищённые Environments/Secrets, существующая совместимая постоянная signing identity и публичный fingerprint, регистрация проверенного dispatcher в main и осознанный ручной запуск на проверенном SHA. Затем проверяются подписанный артефакт и обновление без потери данных. В чат, Git и журналы ключ/пароли передавать не требуется. Подпись и stable release не заявлены; issue #99 остаётся открытым.
