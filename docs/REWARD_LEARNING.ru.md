# Запись с наградой —0.7.7

В web-режиме LocalPilot теперь можно отличать удачные,неудачные,нейтральные и неоценённые примеры. Старые неоценённые записи не объявляются успешными. Основная Android-панель не расширена:оценка находится в web-обучении,через одну кнопку «Оценка / цель ▾».

1. Выберите игру и включите «Запись».
2. Через «Оценка / цель ▾» поставьте действию «Удачно +1»/«Ошибка −1» или настройте автоматический показатель.
3. После записи:STOP → «Обучить» → «По примерам».

## Правила награды

Для растущего показателя,например счёта:
`reward = clip((after − before) / scale, −1, +1)`.

Для расстояния до цели:
`reward = clip((before − after) / scale, −1, +1)`.

Пример:расстояние10→7,масштаб10 — награда+0.3;7→10 — штраф−0.3. Без изменения —0,неизвестный результат —UNKNOWN,который отличается от0. Масштаб положительный и задаёт изменение,соответствующее награде1. Ручная отметка имеет приоритет над автоматической,можно убрать оценку. Формула учитывает измеренное приближение;она сама не определяет семантическую цель любой игры.

В меню «Посчитать награду по двум значениям» можно вручную указать показатели до/после последнего записанного действия,а программа рассчитает знак/размер награды. Открытый диалог связан с определённым примером:если он изменился,оценка не переносится молча на другой.

## Автоматически и ручные исправления

Автоматический показатель работает дляHTML-игр,если на странице есть доступный элемент,содержащий одно число. В расширенной настройке задаются егоCSS-селектор(например#score),направление «Больше/Меньше — лучше» и масштаб. Чтение толькоtextContent,без выполнения пользовательскогоJavaScript. Значение с единицами/несколькими числами,нечисловой результат,недоступный/cross-originiframe/Canvas-показатель не угадываются. Это неOCR.

Чтение асинхронно,ограничено свежестью/тайм-аутом и текущей сессией. Для автоматического вознаграждения используется показатель перед жестом и свежий показатель не раньше200мс после него;пример завершается не раньше400мс после отпускания. Если до проверки произошло другое касание,автоматическая награда не начисляется:неясно,какое действие вызвало изменение. Пользователь всё равно может явно оценить завершённый пример.

Цель и настройки хранятся отдельно поURL/именному профилю. Если в наборе уже есть расчётные оценки по показателю,смена измеряемого элемента/направления/масштаба требует нового профиля. Для неизвестного показателя остаются ручные отметки. Сброс счёта при новом раунде может означать смену эпизода,а не неудачное действие:завершайте запись на границе раунда и исправляйте такие оценки вручную. Победа/проигрыш не выводятся из одногоACK Android.

## Как оценки влияют на обучение

Web-модель остаётся локальной моделью похожих примеров,а неDQN/PPO. Если оценок вообще нет,сохраняется прежний режим повторения демонстраций,с явной пометкой отсутствия оценки результата. Если известна хотя бы одна оценка,действия берутся из положительных примеров;отрицательные не копируются,а запрещают похожее действие в похожей ситуации. Нейтральные иUNKNOWN не становятся положительными демонстрациями. Бóльшая положительная награда даёт приоритет при близких состояниях;сопоставимые противоречащие действия приводят к ожиданию.

Это не взвешивание всей траектории победой/поражением:оценка относится к конкретному действию. Из неудачного раунда нельзя автоматически сделать вывод,что каждый предшествующий ход был плохим. Отчёт отдельно показывает статистику классов,покрытие на отложенной сессии и рекомендации,повторившие известные ошибки. Такая оценка не доказывает выигрыш в реальной игре.

В существующихDQN-симуляторах уже используются численные награды за прогресс/бонусы и штраф за поражение. Их физика,контракт награды и старые чекпойнты этой версией не изменяются. Нативные Android-профили Ари/Карканоида/МаркетРаш/Гошана не получают универсальноеOCR или обученную политику изweb-файла. Автоматические оценки поHTML-показателю не следует объявлять работающими для внешней Canvas-игры в другом приложении.

## Совместимость данных

Наборы с оценками используютLOCALPILOT-WEB-v3:те же256признаков и действия,плюс источник/значение награды и измерения до/после/масштаб. ДляMETRIC-полей декодер заново вычисляет награду и проверяет целостность записи. SHA-цепочка защищает от повреждения,но не доказывает,что импортированные оценки получены в настоящей игре.

v1/v2 по-прежнему читаются и сохраняютUNKNOWN;без добавления оценок их байтовый формат остаётся прежним. При первой записи оценок в существующийv2файл сохраняется отдельный неизменяемый.pre-rewards-v2.bak;обычная.bak/атомарное сохранение остаются. При объединении одинаковый пример дополняется оценкой,не дублируется;противоречащие оценки отклоняются с сохранением исходников. СтарыеAPK v3 не читают,поэтому обратная совместимость файлов оценок требует0.7.7+.

Проверка:автономныеJVM-тесты,сборкаAndroid и компиляцияинструментальныхтестов. На физическомAndroid/WebViewавтооценка ещё не проверена. Никакие реальные удачные/неудачные демонстрации в тестах не подделываются:синтетические признаки служат только проверке алгоритма/формата.
