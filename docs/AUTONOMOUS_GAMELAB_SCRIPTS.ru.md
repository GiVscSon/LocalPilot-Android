# LocalPilot: автоматический игрок и обучение GameLab

## Один запуск (без Android, ADB и Termux)

```bash
bash tools/run_sim_autoplay.sh --out build/reports/sim-autoplay --seed 20261108 --train-episodes 8 --eval-episodes 4 --steps 10
```

Требуются JDK 17+ и Python 3.9+. Скрипт компилирует текущий исходный `GameLabEngine.java` и библиотеку обмена опытом. Он **не** подменяет симуляцию заглушкой, не запускает приложение Android и не может послать жест в настоящую игру.

## Автономный цикл

1. Запускает 10 оригинальных упрощённых игровых сцен `GameLabEngine` с воспроизводимыми seed.
2. Для каждой сцены генерирует допустимые для её механики кандидаты игровых действий. В защищённой сетке клетки `8/9` исключаются.
3. Выбирает действия случайной стратегией, выполняет `tick()` физики и `gesture()`, наблюдает изменение настоящего игрового состояния **только внутри симулятора**.
4. Записывает обучающую последовательность `LOCALPILOT-LAB-EXPERIENCE-v1`; 10 игр × 8 эпизодов × 10 действий = **800 действий** по умолчанию.
5. Обучает отдельную `SimLabPolicy`: для каждой игры, зоны 3×3 и класса действия оценивает частоту подтверждённых откликов. Это простая статистическая contextual-bandit политика, **не** PPO/DQN и **не** обучение визуальной нейросети.
6. Сравнивает случайную стратегию и политику на тех же **удержанных seed**, которые отсутствовали в обучении; 4 эпизода × 10 действий на игру.
7. Для каждой игры считает частоту изменений поля, изменение в процентных пунктах и средний счёт. Результат может быть хуже случайной стратегии. Скрипты обязаны показывать регрессии, а не выдавать любой прогон за улучшение.
8. Отдельный валидатор проверяет исходную маркировку `SIMULATED_GAME`, полноту всех 10 игр, ограничения, контрольные суммы, соответствие цифр CSV и JSON и отсутствие ложного подтверждения настоящих игр.

## Пакет доказательств

- `training-experience.lpx`: исходные обучающие действия симулятора, пригодные для импорта в экран **Игровые модели → Импортировать опыт GameLab** в Android-версии PR #88.
- `evaluation-random.csv`, `evaluation-lab-policy.csv`: независимые игровые эпизоды сравнения.
- `report.json`, `report.md`: машинный и читаемый отчёт.

В GitHub Actions workflow `sim-autoplay.yml` запускает **3 независимых seed** `20261108`, `20261201`, `177777`, отдельную детерминированную повторную проверку и публикует ZIP-артефакты. События `push`, `pull_request`, ручной запуск и ежедневное расписание `03:17 UTC`. Scheduled jobs GitHub запускает из ветки по умолчанию **после слияния workflow**.

## Жёсткие пределы

- До 1024 действий / 512 КиБ на один replay; неизвестная игра или нарушенная строка отклоняется.
- Никакие данные самоигры не пишутся в веса настоящего игрового агента и не отмечаются как Market-успех.
- Android ACK не доказывает движение. Настоящий Market требует отдельно свежего кадра и предметной визуальной проверки через существующие защитные компоненты.
- Сцены `GameLabEngine` упрощены и не гарантируют совпадение с изображениями и физикой игр Яндекс Маркета.
- NES: отдельные JSNES CPU/PPU/контроллерные тесты. Автоматическое обучение на произвольных NES-ROM в этом скрипте не реализовано; DOSBox отсутствует.
- Workflow не публикует стабильный APK автоматически и не сливает PR без приёмки.
