# Аркады и Double DQN

В APK0.4.0 Dev есть четыре оригинальных симулятора и CPU-обучение на Java. Python, сервер, сеть и GPU для телефона не нужны. Это отдельный учебный режим: он не обучается по экрану установленного Doodle Jump и не управляет им.

## На телефоне

Открыть «Аркады · обучать нейросеть», выбрать жанр и нажать «Обучать». Сцена показывает выборку состояния симулятора, а не каждый ускоренный учебный кадр. «Пауза / STOP» сохраняет прогресс; кнопка обучения продолжает его. Уход Activity в фон также ставит обучение на паузу с сохранением. Сворачивание плавающей панели Accessibility — отдельное действие.

«Показать модель» запускает замороженную greedy-политику без обучения. «Оценить ×50» сравнивает её со случайными действиями на одинаковых seed900000..900049, показывает прогресс и парный bootstrap-интервал разницы. Оценка не изменяет веса, replay или RNG тренера. Она может честно показать отсутствие преимущества. Маленький loss не доказывает хорошую игру.

Checkpoints хранятся приватно в `files/arcade-rl/<GENRE>.zip`. Автосохранение каждые30 секунд и при паузе; `.bak` сохраняет предыдущую версию. При повреждении основного файла используется проверенная резервная копия, повреждённый исходник сохраняется с `.corrupt-*`. «Экспорт checkpoint» работает после паузы через системный выбор файла. Старые записи2048 `ppo=false` сюда не импортируются.

## Среды и наблюдения

Жанры: JUMPER, PLATFORMER, LANES, JETPACK. Физика60Hz, одно действие удерживается до4 физических кадров; последний шаг может закончиться раньше из-за гибели. Seed задаёт отдельный xorshift64* RNG. Результат шага содержит observation/reward/progress/terminated/truncated/durationFrames.

Состояние:64 float32, clip[-1,1]. Первые16 признаков описаны в `manifest.json`: положение, скорость, опора, скорость камеры/игры, оставшееся время, комбо, прогресс, полоса, последнее действие, готовность прыжка, резервный ноль и время после приземления. Далее до6 ближайших видимых объектов, каждый dx/dy/ширина/высота/vx/vy/тип/present; отсутствующие заполнены нулями. При равном расстоянии сортировка по стабильному ID. Для вертикальных сцен y относительно камеры; объекты выражены относительно игрока. Это точные признаки собственного движка, не прочитанная память сторонней игры.

| Жанр | Порядок действий | Награда и завершение |
|---|---|---|
| JUMPER | left,right,neutral | Только прирост максимальной мировой высоты/640; бонус+0,1; гибель−1 |
| PLATFORMER | left,right,jump,neutral,left_jump,right_jump | Новая платформа+0,1 и комбо до+0,08; гибель/таймер90с−1; снизу поднимается угроза |
| LANES | left,right,jump,slide,neutral | Выживание+0,01/с, монета+0,02, смертельное столкновение−2 |
| JETPACK | release,hold | Дистанция/360, монета+0,02, близость опасности−0,01/с, гибель−1 |

На2000 шагах среда возвращает truncated, не смерть. Следующий эпизод начинается автоматически, обучение не прекращается. DQN продолжает bootstrap по последнему состоянию при truncated, но не при terminated. Награды суммируются за фактически выполненные физические кадры; gamma0,99 задана на шаг агента. Повторное посещение платформы не даёт награду за новую платформу, прокрутка не даёт награду за высоту.

## Обучение и формат

Double DQN:64→64ReLU→64ReLU→число действий; Huber loss, Adam lr0,001, gamma0,99, batch32, gradient norm≤10. Replay20000 переходов одного жанра, warmup1000, одно обновление каждые4 шага, копирование target каждые1000 обновлений. Epsilon1→0,05 за50000 шагов. У каждого жанра свои веса и данные.

ZIP содержит `manifest.json`, `state.bin`, `SHA256SUMS`. State big-endian: magic/version, жанр, RNG, счётчики/метрики, физическое состояние, веса online/Adam m/Adam v/target и replay с позицией кольца. Загрузка ограничивает размеры, проверяет checksum, конфигурацию, диапазоны и конечность чисел. Для переноса используйте Java API из того же коммита; версия1 не является форматом PyTorch/ONNX.

## ПК и Gymnasium

Это последующий этап после Android; обёртки уже добавлены и вызывают тот же Java-код через JPype. Проверены Python3.12 и JDK21 на Linux; Windows здесь не проверен. Нужен JDK17+.

```bash
python training/build_core.py
python -m venv .venv-rl
# Активировать .venv-rl средствами своей ОС
python -m pip install -r training/requirements-pc.txt
python -m pip install --no-deps ./training/gymnasium
python training/check_gymnasium.py
```

Для установленного Python-пакета задать `LOCALPILOT_CORE_JAR` абсолютным путём к `training/build/localpilot-arcade-core.jar`. В Windows PowerShell: `$env:LOCALPILOT_CORE_JAR = (Resolve-Path training/build/localpilot-arcade-core.jar).Path`.

```bash
python training/train_pc.py --genre JUMPER --steps 10000 --checkpoint /path/to/exported-JUMPER.zip
```

Команда продолжает тот же Double DQN, включая optimizer/replay/RNG; Ctrl+C сохраняет checkpoint. `--evaluate` добавляет оценку50 эпизодов. Gymnasium ID: LocalPilot/VerticalJumper-v0, VerticalPlatformer-v0, LaneRunner-v0, Jetpack-v0. Доступны reset/step; внешнего Android/ADB backend здесь нет.

## Проверка

```bash
java tests/RlVerify.java
java tests/Verify.java tests/legacy_parity.txt
```

RL runner проверяет детерминированность, диапазоны, камеру/награду, прыжок/столкновение, terminal/truncated, численный градиент, уменьшение Huber-ошибки, точное продолжение обучения, восстановление backup, сессию10000 действий и ротацию журнала. Это проверки на JVM, не измерение нагрева/FPS телефона. Длительный эксперимент: собрать core, скомпилировать `training/TrainSmoke.java` с этим JAR и запустить его с числом шагов; отчёты и модели писать в игнорируемую `training/build`.
