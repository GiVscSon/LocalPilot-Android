## Изменения существующего EvaluationGate

1. Пять пилотных сценариев больше не достаточны: требуется минимум **20 пар**
   отдельных сбросов настоящего JSNES. У каждой пары одинаковые ROM, стартовые RAM
   и кадр; у всех пар разные стартовые X и разные epochs для обеих политик.
2. Помимо положительного среднего прогресса, прироста среднего на 0.1 и 60% побед
   по парам, требуется прирост медианы более 5% (абсолютный минимум 0.05 для
   нулевого/отрицательного baseline). Медианы включены в JSON отчёта.
3. Доверенная награда этой конкретной задачи ограничена [-1,1] на 16-кадровый шаг.
   Конечное, но невозможное значение больше единицы не может переполнить сумму
   и превратиться в успешную оценку.
4. В исключение train/holdout входят **state и nextState** обучающего replay,
   включая последний nextState. Раньше парсер собирал только начальные X шагов.
5. Manifest настоящего PPO-кандидата дополнен точными training episode ID, epoch
   и границами кадров. GGUF веса не изменяются.

Стартовые состояния получаются кнопками и выполнением настоящего 6502 кода,
включая короткий warmup 4..15 кадров; прямых записей в RAM нет. Это reset recipes,
а не заявление о поддержке аппаратного ROM seed. Двадцать разных стартовых RAM
не означают обобщения на другие игры.

## Воспроизведение и следующие gates

Существующий workflow `.github/workflows/nes-runtime.yml` уже выполняет оба
реальных сценария через `StudentPpoRealNesVerify` и `StudentHoldoutRealNesVerify`.
Вместо прежних шести пар он теперь получает двадцать. Точный SHA кандидата и
свежие Actions ссылки закрепляются в PR; ссылки выше относятся только к базе.

Не реализованы/не подтверждены этим изменением: живой Android holdout с
атомарным продвижением и откатом PPO, поддержка обучаемого realtime-агента,
произвольные ROM/reward-профили, LoRA/GGUF training, физическая проверка телефона
и планшета, измерения Vulkan/температуры/latency. `adb devices` пуст; аппаратной
проверки в этом чате нет. Предохранитель
`BLOCKED_UNTIL_DEVICE_HOLDOUT_AND_ROLLBACK` сохранён. Общий критерий завершения
Harness ещё не выполнен; зелёная сборка не должна менять этот статус.
