# LocalPilot ONE APK · скриптовый игровой движок

Статус: интеграционный кандидат [PR #89](https://github.com/GiVscSon/LocalPilot-Android/pull/89). Не считать полноценным релизом до завершения однозначных CI и испытаний с реальными играми.

## Что действительно объединено

Основной пакет Android содержит прежние модули управления реальными играми, экран обучения, GameLab с десятью демонстрационными играми и локальный JSNES 2.1.0 для NES/Денди. GameLab теперь открывается прямо из `MainActivity`; отдельная установка `org.localpilot.gamelab` **не нужна для игры в симуляторы и NES**.

Второй APK GameLab остаётся опциональным для E2E-тестов, которым необходимо два приложения, потому что LocalPilot намеренно не использует собственную Activity как внешнюю цель Accessibility.

`app/build.gradle` компилирует фактические исходники GameLab и включает их NES assets; `app/src/main/AndroidManifest.xml` содержит его activity. Никакого независимого второго JSNES не загружается: в общем Gradle build используется существующий pinned `game-lab:bundleVerifiedNesEngine`.

## Один скриптовый центр

Команды доступны из корня GitHub-репозитория, требуются Python 3.10+ и Java 17+:

```bash
# Валидация скриптовой маршрутизации и безопасность реального управления
python3 scripts/localpilot.py unified verify

# Скрипты сами играют в 10 GameLab-сцен, собирают опыт, обучают,
# сравнивают 3 стратегии и маркируют регрессии
python3 scripts/localpilot.py unified selfplay

# Полная проверка уже собранного одного APK, включая 16 пакетов
# симуляционных моделей, NES, manifest и подпись при наличии SDK
python3 scripts/localpilot.py unified apk --apk app/build/outputs/apk/debug/app-debug.apk

# Все три процедуры для уже собранного APK
python3 scripts/localpilot.py unified all --apk app/build/outputs/apk/debug/app-debug.apk

# Запрос CI-сборки на GitHub (требуются gh и gh auth login)
python3 scripts/localpilot.py ci-start
python3 scripts/localpilot.py ci-status
python3 scripts/localpilot.py ci-download
```

`scripts/unified_pipeline.py` сохраняет машинный отчёт в `build/reports/unified-script-engine/`. CI `unified-16-simulators.yml` работает на ветке интеграции и последовательно:

1. Проверяет Java/Python, маршрутизацию 11 реальных игровых профилей и ограничения управления.
2. Запускает воспроизводимые GameLab self-play эпизоды для 10 игр по трём seeds, включая отдельные evaluation seeds.
3. Сравнивает случайную, обученную и сценарную стратегии и создаёт статус карантина при регрессиях.
4. Проверяет 16 модельных ZIP из Git, тестирует адаптивные движки и собирает Android без подмены исходников архивом.
5. Подтверждает, что **основной APK** действительно содержит 16 модельных пакетов, LPS1, GameLab, JSNES, NES-кнопки и правильно подписан.
6. Публикует **один пользовательский APK**, а отчёты self-play сохраняет отдельно. Тестовый companion APK по умолчанию не публикуется в пользовательский артефакт.

## Передача эпизодов внутри APK

После работы с встроенным GameLab его Activity при выходе атомарно дописывает до 1024 ограниченных событий в приватный файл `gamelab-sim-experience-v1.lpx`. Экран моделей LocalPilot при открытии проверяет формат, контрольные суммы, последовательность, имена игр и применяет только `SimLabPolicy` (теневую лабораторную политику).

Экспорт/импорт файла `.lpx` остаётся дополнительным инструментом. Никакой записи напрямую в веса реальных аркад, Q-learning, управление Android или награды Маркета из `SIMULATED_GAME` нет.

## Для реальных игр

LPS1-скрипты задают **маршрут** к встроенному контроллеру конкретной механики, но не командуют произвольными координатами. Реальные разрешения по-прежнему определяют ActionGate, InputPermit, STOP, TTL, валидная ROI и подтверждение действий свежими игровыми кадрами.

Ограниченные и безопасные автоматические восстановления позволяют переживать задержку **неотправленного** кадра и повторный запрос уже выполняющегося захвата, не отключая защиту при смене окна, неверном ROI и неподтверждённом жесте.

Пока нет подтверждения настоящего переноса весов из GameLab на реальные игры или автоматического RL-обучения на произвольных NES-ROM, DOS и SEGA. Для DOS и SEGA части модельного каталога остаются симуляционными профилями, а не полноценными Android-эмуляторами.

## Критерии готовности

- Android build, lint и JVM-сценарии проходят на одном SHA.
- В APK действительно есть ровно 16 адаптивных пакетов и три встроенные GameLab/NES Activity.
- Android API 30/35/36 проверены на том же SHA, что и собранный APK.
- Ни один сценарный или обучающий код не получил возможности отправлять жест без штатной проверки.
- После подтверждения CI остаются испытания настоящих игр и отдельно проверенная стабильная подпись.

Если условия не выполнены, PR остаётся черновиком. Скрипты не объявляют его стабильным релизом.
