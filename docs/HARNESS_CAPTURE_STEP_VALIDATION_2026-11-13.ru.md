# Harness: захват и граница STOP · 13.11.2026

Рабочая база: PR #123, `9093118dd7622316190ac11e7b8f37a3c456d7e0`.
Продолжение находится в `fix/harness-capture-acceptance-20261113`.
Это исправления существующего Harness, одного пользовательского APK и его
тестового companion. Релиз и завершение фаз 0–6 не объявляются.

## Подтверждённые причины и изменения

1. Диагностический preview создавался размером с ROI. Для 1080×2400 это
   10 368 000 байт ARGB, а экспорт DiagnosticBundle допускает максимум
   720 по стороне и 345 600 пикселей. Общий расчёт DiagnosticFrameSize теперь
   ограничивает оба capture-маршрута и retained refusal frame. Пример после
   уменьшения: 324×720, 933 120 байт. Полноразмерный кадр компьютерного зрения
   и его экранные координаты сохранены. Это не измерение общей пиковой памяти:
   одна полная программная копия HardwareBuffer всё ещё нужна CPU readers.
2. Читатель результата мог синхронно остановить сеанс, после чего screenshot
   callback заново сохранял diagnosticFrame. После возврата читателя повторно
   проверяются epoch, состояние захвата, focus и ROI. Отозванный сеанс не
   восстанавливает диагностические пиксели.
3. Пустые и инвертированные границы окна теперь отклоняются. Валидное частичное
   окно использует существующий display capture. Размер HardwareBuffer
   проверяется до выделения программной копии.
4. Временный refusal bitmap освобождается и при исключении Canvas. Ошибка
   диагностики не выдаёт разрешение на ввод.

## Android-проверки на новом SHA

В существующий harness-window-capture workflow добавлена отдельная матрица
API 30/34/35/36 на x86_64 эмуляторах. Она вызывает реальные Android screenshot
API, проверяет пиксели и геометрию собственного тестового окна, поздний callback
после STOP, смену владельца окна, STOP внутри читателя и защищённое содержимое.
Режим только наблюдает: автоматические жесты и InputPermit запрещены.

До завершения Actions эти строки имеют статус NOT RUN. Подготовленный runner
не считается выполненной приёмкой. Локальная Gradle-сборка встретила сетевую
ошибку загрузки AndroidX WebKit 1.18.0; версия зависимости не подменялась.

Phase 0 теперь повторно проверяет APK при изменении app/game-lab/shared
исходников и сохраняет фактически проверенный APK вместе с SHA-256, отчётом
упаковки и результатом apksigner. Это debug-подпись, не постоянная release.

## Оставшиеся ограничения

Физическое устройство не подключено. Нет доказательства Vulkan на POCO,
пригодности StudentPolicy/PPO или полного офлайн-контроля всех сетевых клиентов.
Защищённое signing environment и совместимый постоянный ключ недоступны
текущему подключению. PR #106 уже объединён в main `189b3b0a…`; keyless
unsigned build этого другого кандидата не является подписанным Harness APK.
Все будущие результаты фиксируются с точным source SHA, без переноса статуса
предыдущего PR на изменённый код. `release_ready=false`.
