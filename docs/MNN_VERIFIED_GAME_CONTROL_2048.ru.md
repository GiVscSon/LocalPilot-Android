# MNN-Pocket как проверяемый игровой агент LocalPilot

## Первая игра: 2048

MNN-Pocket 0.3B, встроенная в ARM64 APK, теперь может **предлагать действия для реального 2048**. Модель получает только 16 распознанных значений клеток (0 для пустой) и список допустимых направлений; сырой скриншот и доступ к Android жестам ей не передаются.

Ответ генерируется на английском, с ограниченной грамматикой GBNF: только одно из LEFT, UP, RIGHT, DOWN. Неверный/пустой ответ не даёт полномочий на ввод. У модели нет доступа к Android Gesture API или разрешению InputPermit.

Путь решения:

1. LocalPilot читает две устойчивые версии поля и получает исходное `Board2048`.
2. Надёжный CPU-планировщик выбирает `baseline`, учитывая предыдущие неответившие направления.
3. Встроенная MNN асинхронно предлагает одно направление в отдельной очереди, не блокируя основной поток.
4. После ответа приложение **снова** читает два устойчивых кадра. Если поле изменилось или привязка/эпоха STOP устарела, ход не отправляется.
5. `Neural2048Verifier` проверяет точность формата, легальность, маску исключений, отсутствие no-op, количество пустых клеток и объединения, сохранение углового максимума. Отвергнутое предложение заменяется CPU baseline только после свежего кадра. Серьёзные несоответствия приводят к пропуску и перечитыванию.
6. Только штатный `send` с новым тикетом ActionGate, InputPermit и TTL отправляет один жест.
7. После Android ACK применяется уже существующая `Board2048.verification`: подтверждение ходов, проверка ожидаемого поля и новой 2/4, защита STOP и учёт стагнации. **ACK никогда не является подтверждением игрового эффекта.**

Режим **выключен по умолчанию** и требует явного включения: LocalPilot → Локальное ИИ-ядро → «Включить / выключить MNN 2048». При переключении во время игры выполняется STOP, затем нужно снова выбрать окно и запустить игру. Настройка не сохраняется после остановки самой службы или перезапуска Android.

## Что означает «достаточно быстрая»

Пиковая скорость токенов не равна задержке управления. До первого ответа нужно загрузить веса, обработать промпт и дождаться завершения декодирования. Поэтому **для 2048 допустимо несколько сотен миллисекунд или больше**, после чего поле читается заново. Для FLAPPY/PADDLE/TRAFFIC такой подход слишком медленный. Там продолжают действовать быстрые физические контроллеры, а MNN в будущем может изредка обновлять высокоуровневую стратегию вне кадрового цикла.

## Критерии допуска

- Один исходный SHA с PASS обычной Android сборки, JNI грамматики и 2048 smoke, JVM контрактов, эмуляторов API 30/35/36.
- На реальном ARM64 устройстве тест без Termux и сети, с включением и отключением режима, неверным предложением, изменением поля во время генерации и принудительным STOP.
- Отдельно проверить, что реальный ход засчитывается **только** после правильного изменения поля. Сравнить серию с baseline CPU и нейросетью по количеству ходов, успехов, остановок, задержке каждого решения.
- Система пока не обучает GGUF-веса MNN, не превращает её в компьютерное зрение и не даёт управление всеми десятью играми.

Вне 2048 функциональность остаётся прежней, и все инварианты STOP, ROI, ACTIONGATE, INPUTPERMIT, TTL и UNKNOWN сохраняются.
