# GameLab → LocalPilot: обмен лабораторным опытом (v1)

## Назначение

Это первая **реально подключённая**, но полностью изолированная дорожка опыта между двумя установленными Android APK. Она не обходит Android Accessibility, ActionGate или разрешение пользователя.

1. Откройте GameLab и выполните движения в любой из десяти сцен.
2. Нажмите **«Опыт GameLab»** рядом с кнопкой «Ретро» и сохраните `localpilot-gamelab-experience.lpx` через Android SAF.
3. Откройте основной LocalPilot → **«Игровые модели · обучение и экспорт»** → **«Импортировать опыт GameLab (.lpx)»**.
4. Выберите файл. LocalPilot проверит формат, порядок, диапазоны и SHA-256 каждой строки, затем обучит **отдельную лабораторную contextual-bandit политику** на статистике откликов.
5. Отчёт останется доступен после повторного открытия: исходный проверенный журнал сохраняется атомарно в приватных файлах основного приложения и при загрузке пересчитывается.

## Контракт и ограничения

- Заголовок строго `LOCALPILOT-LAB-EXPERIENCE-v1`. Это **не** реальная телеметрия Маркета и не доказательство награды.
- До 1024 событий; размер до 512 КиБ; последовательная нумерация; контроль SHA-256 каждой строки. SHA-256 служит только для контроля целостности, **не** криптографическим подтверждением источника.
- Записываются идентификатор GameLab-сцены, тип искусственной ошибки стенда, координаты ввода, длительность, два хеша состояния, изменение счёта и реакция симулятора.
- Действия при `INPUT_IGNORED`, `FROZEN_VIEW` и `PANEL_OVERLAP` **исключаются** из обучения.
- Учебная политика группирует действия по игре, зоне 3×3 и категории TAP/LEFT/RIGHT/UP/DOWN; рекомендует действие только если в зоне есть хотя бы три наблюдения данного действия.
- Результат импортируется в самостоятельный лабораторный файл `gamelab-sim-experience-v1.lpx`. Он **не** записывается в `ArcadeLearningStore`, `RealGameNeuralCritic`, `PaddleTransfer`, `InputPermit` или `PilotService`.
- Анализ GameLab — первый рабочий канал обмена, **не автоматический перенос управляющих весов** и не релизная приёмка реальных игр.
- NES/Денди пока остаются отдельным наблюдаемым эмулятором, а не источником записей этого формата: кнопки эмулятора требуют другой схемы действий. DOSBox всё ещё отсутствует.
- Прежде чем разрешать shadow-политике влиять на настоящие игры, нужны отдельные сопоставление форматов состояния/действия, офлайн-регрессии по реальным кадрам и сравнение A/B без права самостоятельного ввода.

## Проверки

`java tests/SimExperienceVerify.java` проверяет roundtrip, checksum, строгую схему, запрещённые игры, несогласованные отклики, ограничения координат, исключение искусственных ошибок стенда и изоляцию рекомендаций. GitHub Android workflow запускает этот тест как обязательную регрессию.

GameLab остаётся отдельным пакетом `org.localpilot.gamelab`, не изменяет системные разрешения и не выдаёт результат симуляции за подтверждение настоящей игры.
