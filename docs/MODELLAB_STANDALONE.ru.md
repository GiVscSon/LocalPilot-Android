# ModelLab: отдельное Android-приложение для локальных нейросетей

**Постоянный идентификатор:** `org.localpilot.modellab` (никаких `applicationIdSuffix`).

Это отдельное приложение, не требует установки LocalPilot и **не содержит** `PilotService`, `AccessibilityService`, доступа к игровым жестам, оверлея или чтения чужого экранного потока. Собственное приватное хранилище и один нативный GGUF-движок llama.cpp. Игровой LocalPilot остаётся неизменным.

## Два установочных пакета

- `ModelLab-Preloaded-AllModels`: 4 модели GGUF уже внутри APK (MNN-Pocket 0.3B, Qwen3.5-0.8B, LFM2.5-350M, LFM2.5-VL-450M + mmproj). Можно сразу выбрать модель, проверить текст или вручную открыть фото. Нет повторной загрузки предустановленных весов из сети.
- `ModelLab-Import-Only`: компактный APK без весов. Добавляй локальные GGUF через системный проводник или по публичной HTTPS-ссылке Hugging Face.

**Оба пакета имеют один и тот же фиксированный package ID.** Они не устанавливаются одновременно и пока подписываются отдельными временными debug-ключами GitHub Actions. Чтобы обновлять один пакет другим без переустановки и потери приватных импортов, требуется постоянный signing key. Нет возможности безопасно обещать обновление между произвольными CI-сборками.

## Импорт других моделей

- Системный Android-пикер открывает `.gguf`, копирует в приватную директорию, проверяет магию GGUF и вычисляет SHA-256. Можно заранее ввести ожидаемый SHA-256 для сравнения.
- По явному нажатию пользователя можно загрузить публичный прямой GGUF URL с `huggingface.co` по HTTPS. Редиректы разрешены только на определённые доверенные Xet/HF CDN; HTTP и локальные/IP-адреса запрещены.
- Максимальный размер одного импортируемого файла: 3,5 ГБ. Нужен запас свободного места. Импортированные модели не появляются в игровом приложении.
- Для мультимодальности импортируй GGUF и затем совместимый `mmproj*.gguf`; это могут быть два разных файла. Анализ вручную выбранной фотографии ограничен 640×640 RGB.
- **Только GGUF:** ONNX, TFLite/LiteRT, MNN и MediaPipe не поддерживаются текущим нативным `llama.cpp`. Они требуют отдельных runtime-адаптеров. Даже корректный GGUF не гарантирует поддержку архитектуры на закреплённой версии llama.cpp.
- Сами веса GGUF могут быть повреждены или непроверенными. Модели из неизвестных источников не обладают гарантированной безопасностью, а их лицензии нужно проверять.

## Сборка

```bash
./gradlew -PincludeModelLab=true :model-lab:assembleDebug
./gradlew -PincludeModelLab=true -PmodelLabPreloaded=true :model-lab:assembleDebug
```

Перед сборкой нужен закреплённый `third_party/llama.cpp` и Android NDK. Для полной сборки сначала выполни `python3 tools/bundle_embedded_gguf.py prepare` и `python3 tools/bundle_optional_models.py prepare`.

GitHub Actions: `.github/workflows/model-lab-android.yml`. Не считать релизом до успешного CI, теста открытия фото с реальной VLM и испытаний на POCO X7 Pro (12 ГБ RAM).

## Mali-G720 GPU: экспериментальный Vulkan backend

В POCO X7 Pro установлен Mali-G720 и 12 ГБ RAM. GGUF модели можно протестировать с Vulkan offload, но CPU остаётся надёжным режимом по умолчанию. Обычные APK никак не используют новый backend.

В ModelLab добавлены:
- **CPU**, **Vulkan GPU8**, **Vulkan GPU16**, **Auto**. GPU16 означает попытку перенести 16 слоёв трансформера на GPU, а не обещание их полной совместимости.
- Кнопка проверки устройства через ggml backend enumeration. Если реальная Vulkan-библиотека отсутствует, выбирается CPU.
- Бенчмарк **одного и того же** фиксированного английского промпта на CPU и GPU8; фиксируются времена полного ответа и факт `nativeLoadedGpuLayers()>0`. **Auto** использует GPU только если тот реально отработал и показал меньшее время на этой модели. Данные измерений не переносятся на другие модели.
- Отдельный экспериментальный workflow `.github/workflows/model-lab-vulkan.yml` собирает GPU-вариант с `-PincludeModelLab=true -PmodelLabVulkan=true`, CMake `GGML_VULKAN=ON`. При отсутствии shader compiler/SPIRV-Headers сборка не должна подменять GPU на CPU молча.

**Ограничения:** драйверы Mali при фоновой GPU-нагрузке способны зависать. Нативный Vulkan crash или блокировка GPU-очереди может быть неустранимым из того же процесса. Поэтому использовать GPU-режим только в отдельном ModelLab, не сворачивать его во время теста и не направлять его вывод в игровые жесты. GPU-прирост нельзя утверждать без замера на конкретном POCO. Обе версии APK имеют один ID `org.localpilot.modellab`, поэтому для обновлений нужен общий стабильный ключ подписи.

Отдельный чип NPU MediaTek не равен Vulkan GPU, для него требуется отдельный runtime и поддерживаемая модель. Он здесь не активирован.


## Единая предзагруженная версия с Vulkan

Экспериментальный workflow `.github/workflows/model-lab-vulkan.yml` теперь проверяет **две** сборки одного приложения `org.localpilot.modellab`:

1. `ModelLab-Vulkan-Experimental-ARM64`: небольшой APK с Vulkan backend и импортом пользовательских GGUF.
2. `ModelLab-Vulkan-All-Models-Offline`: **полный** APK с Vulkan, MNN-Pocket, Qwen3.5-0.8B, LFM2.5-350M, LFM2.5-VL-450M, подходящим `mmproj`, NES-эпизодами и возможностью импорта других GGUF. Все модели сверяются с закреплёнными SHA-256 до публикации артефакта. Приложение не получает доступ к игровым жестам.

Обе версии одного приложения нельзя установить рядом. На этапе CI для них используется непостоянная отладочная подпись: переход от одной версии к другой может требовать удаления первой (при этом потеряются её приватные импорты). Для удобных обновлений нужен закреплённый release key. Эта экспериментальная сборка не гарантирует ускорения на Mali-G720 без испытания на физическом POCO X7 Pro.


## Основная установка: небольшой APK + модели по выбору (11.11.2026)

**Рекомендуемый вариант:** `ModelLab-Import-Only`, примерно 18 МБ по предыдущей CI-сборке; новый CI отклоняет APK больше 40 МиБ и APK со встроенными GGUF. Весовые файлы не скачиваются до явного нажатия пользователем. Для работы используется единый ARM64 `llama.cpp`, без облачной генерации.

На главном экране есть «Проверенный каталог» и кнопка «Скачать выбранную модель по проверенной ссылке». Все файлы берутся с `huggingface.co` по **неизменяемой ревизии Git**, не по `main`; сверяются точный размер, заголовок GGUF и SHA-256. Список:

- MNN-Pocket 0.3B GGUF: 192 МБ, `taobao-mnn/MNN-Pocket-0.3B-GGUF`.
- Qwen3.5-0.8B GGUF: 563 МБ, `ggml-org/Qwen3.5-0.8B-GGUF`.
- LFM2.5-350M GGUF: 219 МБ, `LiquidAI/LFM2.5-350M-GGUF`.
- LFM2.5-VL-450M GGUF: 219 МБ плюс 103 МБ `mmproj`, оба скачиваются одним действием (322 МБ), `LiquidAI/LFM2.5-VL-450M-GGUF`.

Ревизии и контрольные суммы закреплены в `ModelLabPresetCatalog.java` и подтверждены существующими скриптами `bundle_embedded_gguf.py` / `bundle_optional_models.py`. Повторное скачивание уже проверенной модели пропускается. При ошибке SHA-256, размера, разрешений CDN или GGUF файл не регистрируется как рабочий. Реестр импортов сохраняется через Android `AtomicFile`.

Отдельная «полная» APK более 1,3 ГБ оставлена исключительно для ручного архивного теста; **она не нужна для обычной установки**. CPU по умолчанию. Vulkan по-прежнему отдельный эксперимент и не требуется для реальных NES-игр.

**Проверка приёмки:** успешно собрать компактный APK, скачать Qwen и LFM-VL с обоими файлами, получить реальный текст/анализ фотографии на POCO X7 Pro, проверить сохранение моделей после перезапуска и затем выполнить передачу NES-эпизода. Зелёная CI-сборка не заменяет этот тест.


## Сквозной режим NES → ModelLab Vision (новый)

В GameLab запусти настоящий NES ROM или оригинальный тестовый homebrew, выполни ручной ход и нажми **«NES → ModelLab · передать проверенный эпизод»**. Вместе с ограниченным `NesTrial` GameLab передаст через явный Intent уменьшенный до 128×120 PNG текущего NES-экрана, если WebView успешно его получил. Формат, размеры, CRC-32 чанков и лимит 150 000 байт проверяются независимым `NesFrameTransfer`. Скриншот **не содержит достоверной информации о победе или причинности хода** и не обязательно соответствует точному кадру его окончания. Оригинальный ROM и пути к пользовательским файлам не передаются.

В ModelLab полученный снимок отображается автоматически. Для разбора пикселей выбери модель со зрением, например **LFM2.5-VL-450M вместе с mmproj**, и нажми **«Анализировать фото локально»**. Кнопка «Объяснить последний NES-эпизод» по-прежнему анализирует только текстовые метаданные; это два разных теста. Если PNG испорчен, доступен текстовый отчёт. При новом эпизоде старый снимок очищается, чтобы его нельзя было принять за новый. Вся генерация остаётся внутри отдельного ModelLab без игровых разрешений.

Передача выполняется только по нажатию. GameLab и ModelLab используют возврат в существующую Android-задачу, если она уже запущена. Никаких автоматических управляющих команд LLM в LocalPilot этот мост не добавляет.

### Ручная проверка трёх установленных приложений

С подключённым через ADB POCO X7 Pro выполни:

```bash
python3 tools/device_triad_acceptance.py --serial SERIAL
```

Где `SERIAL` берётся из `adb devices`. Скрипт проверяет установку LocalPilot, GameLab и ModelLab, пытается открыть их публичные главные экраны и проверяет, что настоящий композитор Android отдаёт PNG-кадр. Личные снимки **не сохраняются**; на диск попадает только `build/reports/device-triad-acceptance.json` со статусами и размерами. Команда не нажимает игровые кнопки, не меняет разрешения и не делает вид, что реальная генерация GGUF или обучение проверены автоматически.

Локальный host-тест сценария без устройства: `python3 tests/test_device_triad_acceptance.py`. Дополнительно CI проверяет `tests/nes_visual_bridge_smoke.cjs` и `tests/NesFrameTransferVerify.java`; физические проверки ROM, VLM, GPU и подписанного обновления по-прежнему обязательны.
