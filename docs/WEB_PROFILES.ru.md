# Отдельные игры в web-обучении · 0.7.4 Dev

Пользователь подтвердил, что полученный .lpweb содержит разные мини-игры. В прежнем коде идентификатор набора определялся только хешем URL. В общей SPA-странице это объединяет несовместимые действия в одну модель. Обнаружено смешение по устройству данных, а не доказана причина каждого отказа нативных аркад.

## Новый сценарий

1. Откройте web-игру и выберите её через «Игра ▾».
2. Нажмите «Запись» и играйте только в эту игру; перед другой мини-игрой выберите её профиль.
3. STOP → «Обучить» → «По примерам».

Предлагаются распространённые названия и «Добавить свою игру». Это названия наборов демонстраций, а не заявление, что для каждой игры реализован нативный адаптер. Выбор профиля ручной; автоматическое определение смены мини-игры внутри SPA пока не реализовано. При полной навигации страницы выбор сбрасывается, при явной смене профиля отменяется прежняя запись/жест/подсказка, очищаются модель и кадр. Модель проверяется по URL и profile-ID перед игрой.

## Формат и хранение

LOCALPILOT-WEB-v2 сохраняет прежние256 признаков, типы действий и13 полей каждой строки. Заголовок:версия,схема признаков,URL-hash,origin,profile-ID,profile-name. SHA256-цепочка включает заголовок. Имя нормализуется NFKC,обрезается/схлопываются обычные пробелы;ID=SHA256 имени в lowercase(Locale.ROOT). Профили с разными именами и тем же URL изолированы; case/совместимые Unicode-формы одного имени не создают разные пути. Управляющие символы,переносы,биди-format и имена длиннее64UTF-16 символов отклоняются.

Файлы:web-lessons-v2/<url-hash>/<profile-id>.lpweb. Название не становится путём файла.1000 примеров/8MiB на один профиль; до32 именованных профилей в меню одной страницы. Atomic save/backup сохранены. Объединение требует совпадения URL/origin/profile-ID. Файл v2 требует0.7.4+; старое приложение не понимает новый заголовок.

Кодирование больших экспортов, проверка/объединение и сохранение выполняются в фоне. Смена профиля/STOP/навигация отменяют применение запоздалого результата импорта. Отложенное сохранение относится к исходному объекту профиля, а не к выбранному позднее набору.

## Старый смешанный файл

v1 по-прежнему читается, но считается неназначенным:predict возвращает отсутствие действия, trainReport требует явного назначения. Новый профиль начинает с собственных данных и не наследует прежний URL-only набор. Оригинальные web-lessons/<hash>.lpweb и backup не переписываются при открытии профиля. Импорт v1 сначала архивируется отдельно; архивы доступны через «Игра ▾» → «Старый набор этой страницы…» и экспортируются целиком.

Для переноса копии:выберите целевую игру → откройте старый набор/импорт → «Выбрать сеанс» → выберите сеанс → подтвердите, что он целиком относится к этой игре. После этого только выбранные строки копируются в профиль. Для legacy допускается явно назначить записи новому URL на том же origin; первоначальный файл остаётся в архиве. Именованный v2-файл нельзя переназначить другой игре этим путём.

Один сеанс не обязательно равен одной игре. Если внутри сеанса тоже смешаны игры или назначение неизвестно, оставьте его в архиве. Программа не угадывает реальные названия старых записей. Новую размеченную запись можно сделать отдельно; исходные1000 примеров не удаляются.

## Проверки и пределы

WebLesson46 + WebProfiles55 + WebHTTP29 =130 JVM assertions PASS. Регрессии:противоположные действия для одинакового наблюдения в двух профилях одного URL, запрет cross-profile merge, v2 roundtrip/metadata integrity, v1 byte roundtrip/quarantine, явное копирование сеанса, legacy preservation/backup/archive, отдельные пути и неверная идентичность файла. HTTP-тесты используют имитацию HTTPS, не реального провайдера.

На реальном пользовательском файле1000 строк/6 сеансов проверены:побайтовый roundtrip v1, сохранность оригинала/архива, отсутствие автоматического обучения/действий и отсутствие смешанных строк в двух новых именованных профилях. Названия игр этим данным не присваивались. Пользователь подтвердил смешение разных игр; прежние35 рекомендаций/506 относятся к смешанному набору и не являются чистой оценкой одной игры.

Android UI/SAF, смена профилей на телефоне, настоящий WebView и успешная игра НЕ проверены физически. Классификация игры, улучшение nearest-example политики и native Arcade/RL-перенос остаются отдельными задачами.
