# Harness Phase 3A: проверяемая целевая награда для собственной NES homebrew

**Статус: experimental / task-specific.** Это первая узкая задача с числовой наградой, а не универсальный reward для NES, PPO или релиз.

## Происхождение
- Только `HomebrewNes.cartridge()`, созданная локально в приложении: приложение проверяет полное равенство байтов перед разрешением режима homebrew. Внешние ROM, включая скачанный проверенный VOID LANCER, **не** получают этот профиль.
- В самом 6502-коде домашней ROM координаты спрайта находятся в zero-page `$01` (X) и `$02` (Y), начальные (128,112). Чтение выполняет настоящий JSNES 2.1.0 до и после **точно 16** эмулированных кадров, после отпускания кнопки, без таймера или подделанного ACK.
- Целевая точка лабораторного задания: **(192,112)**. Расстояние = |x−192| + |y−112|. Награда = уменьшение этого расстояния за шаг; при первом достижении дистанции ≤2 начисляется дополнительная явно заданная task-бонусная величина 20. Это **разработанная задача навигации**, не счёт игры и не внутренняя награда произвольного ROM.
- Android `HomebrewGoalReward.verify()` отдельно проверяет допустимую кнопку, epoch, 16 кадров, 8-битные координаты, направление и максимальную скорость. Только после `HarnessCoordinator.complete()` и свежего NES-кадра эта запись может попасть в `ConsoleExperienceMemory.appendGoal()`.

## Единый контур хранения
Старый `console-ai-experience-v2.log` остаётся в прежнем виде с `UNKNOWN` reward. Дополнительный файл `console-homebrew-goals-v1.log` принадлежит **тому же общему ConsoleExperienceMemory**. Каждая goal-запись привязана к ROM-epoch, GGUF ID/SHA, настоящему ходу, кадрам до/после и наблюдаемому CPU-состоянию. Формат строго типизирован, ограничен 128 КиБ, с SHA-256 checksum и перепроверкой математической функции награды при чтении. При повреждении обучение блокируется. Другой компонент не получает права придумывать reward.

Один Harness Console показывает CPU-состояние и награду отдельно от legacy `PIXELS_DIFFER`. ModelLab и GameLab используют прежний общий STEP/STOP-контроллер.

## Приёмка и границы
- JVM: целевой reward, противоположное движение, A/B без движения, достижение цели, подделанные состояния/кадры, контрольная сумма и replay.
- Node + JSNES: фактический NROM 6502/PPU, реальное движение вправо и порядок callback `onHomebrewTask → onAgentAction → onFrame`.
- Android CI: All-in-One ARM64, одно приложение и UI-эмулятор, API30/35/36; не заменяют физический POCO X7 Pro.
- **Ещё не реализовано:** обучение новых весов на этих переходах, проверка обученной политики на отдельных реальных NES-эпизодах, универсальный reward для чужих ROM и CPU/Vulkan benchmarking. Следующая фаза обучает и оценивает policy на этом уже проверяемом task dataset.
