# Восстановление геометрии Bubble после изменения изображения

Продолжение d28c3fc. Раньше неудачное чтение по сохранённой геометрии повторялось на каждом кадре с теми же координатами. После сдвига или изменения масштаба автоматическое восстановление не выполнялось.

BubbleVision.Read теперь различает геометрический отказ и неизвестный игровой класс. При геометрическом отказе чтения по предыдущему полю выполняется один повторный геометрический поиск на текущем кадре. Максимум одно чтение по подсказке и одно полное приобретение геометрии; рекурсии нет. Цветовая маска для поиска не используется.

Круглый предмет неизвестного класса не запускает повторный поиск и не исчезает из поля. Перекрытие панели блокирует чтение до обращения к пикселям. Восстановление координат не сбрасывает BubbleSession: два свежих устойчивых кадра нужны заново. При ожидающем выстреле другая геометрия даже с точно ожидаемым массивом цветов не подтверждает результат; исходный срок ожидания сохранён.

Локально на окончательном коде: 19/19 JVM/tooling наборов PASS; 72 проверки формы/поиска, 286 board/policy/feedback, 1476 независимых проверок отскока. Добавлены 22 проверки сдвига, масштабов 0.98/1.02, текущих координат пушки, повторной стабилизации, отказа ложного post-ACK подтверждения, временного непрозрачного перекрытия и неизвестного круглого класса без полного поиска.

Частный размеченный кадр: последовательность масштабов 0.75 → 1 → 1.5 с передачей старой геометрии в следующее чтение — 603 утверждения PASS. Каждый раз 58 шаров и зелёная пушка, все клетки совпадают. Два последних перехода явно возвращают «Геометрия восстановлена». Пиксели не публикуются.

Native build/API30/35/36 нового SHA требуют отдельной проверки; актуальные результаты — в PR #27. Старые матрицы d28c3fc не относятся к новому коду. Физическая игра NOT RUN, обратные ряды остаются наблюдением. Это ограниченное восстановление геометрии Bubble, а не универсальное сопровождение произвольных объектов.

Повторение: `java tests/BubbleVerify.java`; полный JVM/tooling список — `.github/workflows/android.yml`. Далее: native приёмка, сверка установленного signer и телефонного ROI, пять физических post-ACK VERIFIED действий, независимая квалификация обратных рядов и сложных временных последовательностей.
