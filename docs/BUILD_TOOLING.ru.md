# Единая сборка и упаковка

Версию, versionCode, package suffix и SDK-уровни инструменты читают из
app/build.gradle. Поддержаны текущие буквальные значения Groovy; неоднозначные
или отсутствующие значения вызывают ошибку. Не поддерживается исполнение
произвольных Gradle-выражений из Python.

## Сборка

```bash
python3 build_debug.py
```

Запускает Gradle assembleDebug, lintDebug и компиляцию Android-тестов. Затем
проверяет целостность APK, фактические package/versionName/versionCode/minSdk/
targetSdk через aapt и подпись через apksigner. Использует исходный AndroidManifest
и обычный ключ Gradle; независимая сборка через aapt2/d8 с отдельным ключом удалена.
SDK: ANDROID_HOME/ANDROID_SDK_ROOT либо --sdk. Установленный Gradle можно выбрать
через --gradle; доступен --offline. --output принимает только новый путь.

## Упаковка

```bash
python3 tools/package_release.py --expected-certificate SHA256_ВАШЕГО_СЕРТИФИКАТА
```

Без --expected-certificate проверяется валидность подписи, но её соответствие
ранее установленной версии не предполагается. В CI ключ может быть временным.
Перед публикацией APK для обновления проверка ожидаемого сертификата обязательна
для процесса выпуска; его значение публично и не является приватным ключом.

Новая папка release/LocalPilot_Android_<версия>_dev содержит APK, ZIP актуальных
исходников, MANIFEST.json (коммит, признак локальных изменений, версия, сертификат,
SHA256 и размеры файлов), SHA256SUMS и общий ZIP. Существующий выпуск не заменяется;
для повторной проверки укажите другой --output. Старые плоские файлы release/
не изменяются. Упаковщик не создаёт и не обновляет GitHub Release автоматически.

В исходный архив входят текущие отслеживаемые файлы и неигнорируемые новые файлы
исходников/документации; локальные изменения сохраняются, удаления учитываются.
Не включаются кеши, сборки, ключи, .env, конфигурация SDK, записи экрана, изображения,
локальные журналы, архивы диагностики, типовые бинарные обучающие данные.
Новые неотслеживаемые файлы данных не включаются. Символические ссылки и известные
шаблоны секретов приводят к отказу упаковки. Размер одного файла ограничен 16 MiB.
Это не универсальный детектор секретов: перед публикацией нужен просмотр состава.

Проверка версии APK не доказывает соответствия его Java-кода рабочему дереву,
если исходники поменялись без увеличения версии. Сначала всегда выполняйте сборку,
затем упаковку; MANIFEST отражает состояние дерева, а не выдуманное доказательство.

## CI

Workflow использует JDK21/Gradle8.9 и SDK стандартного Ubuntu runner, устанавливает
нужные пакеты, выполняет Python-проверки инструментов, JVM Verify/RlVerify и новые
Grid/Learning/Result/Universal/Controller/SystemVerify. После сборки упаковывает
проверенный APK и исходники; lint-отчёт сохраняется также при ошибке.
Физические Android-тесты этим workflow не выполняются.

По API GitHub старый запуск 39942639162 завершился на шаге setup-android@v3.
Скачивание подробного журнала блокировалось Forbidden. Этот шаг заменён
использованием уже установленного SDK, но точная исходная причина не установлена;
результат нового CI нужно проверять по фактическому запуску, а не по YAML.

Тесты инструментов:
```bash
python3 -m unittest discover -s tests -p test_release_tools.py -v
```
