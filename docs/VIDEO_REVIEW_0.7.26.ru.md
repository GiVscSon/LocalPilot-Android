# Проверка записей пользователя для 0.7.26

Просмотрены пять предоставленных MP4, включая обзорные кадры всей длительности
и соседние кадры около проблемных событий. Все записи 1220×2712, примерно
24.2 кадра/с (частоты из ffprobe; временные позиции указаны в секундах записи).
Исходные MP4 и извлечённые изображения не включены в Git/архив исходников.

- 00-36-47 (16.86 с): около 0.51 с виден READ/AUTO_BOARD_MISSING на цветном
  поле с двумя плитками 2. Это подтверждает отказ чтения в старом запуске,
  но не доказывает появление 32 или причину отказа. Нужны ручной ROI и
  проверенный цветной профиль; стандартный локатор не обещает читать этот скин.
- 00-40-45 (15.79 с): пузырьки движутся, счёт меняется 0 → 3 → 7.
  По записи нельзя установить источник касаний. Поддержка пузырьков этим
  не доказана и в текущую итерацию не добавлена.
- 00-44-03 (17.60 с): в 0.53 с виден экран результата за панелью,
  кадры379 / READ375 / ввод1 / ACK1; позднее открывается меню LocalPilot.
  Эти счётчики не являются доказательством качества игры или источника ошибки.
- 06-37-33 (26.28 с): в 5.00 с, на экране результата, явно виден
  STOP [TARGET_WINDOW_UNAVAILABLE], кадры2998 / READ2987 / ввод291 / ACK291.
  В обзорных кадрах 5.78..25.23 с виден системный запрос трансляции.
  Видеоряд подтверждает сообщение, но не длительность реального отсутствия
  focused window; это проверяется отдельным сценарным тестом WindowFocus.
- 06-38-35 (18.72 с): соседние кадры 3.70, 4.12 и 4.60 с показывают
  CAPTURE/ARCADE_CAPTURE_STALLED на экране результата, кадры834 / READ829 /
  ввод82 / ACK82. После этого открывается запрос трансляции.
  Статичный экран может не порождать новые MediaProjection-кадры; точную
  причину остановки старого процесса и reason13 видеоряд не устанавливает.

Проверки по наблюдениям: временное отсутствие окна 0..599 мс без нового ввода;
600 мс/смена геометрии/блокировка — STOP; пользовательское согласие через
45 секунд; готовность службы и первого кадра до 15 секунд на этап;
три отсутствующих поля → Searching, два устойчивых восстановленных кадра.
Проверка этих сценариев в JVM не заменяет повтор на исходном телефоне.
