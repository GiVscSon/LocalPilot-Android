# Границы свежего кадра · аудит

JumperCaptureService декодирует полный уменьшенный кадр MediaProjection. PilotService использует Bitmap целиком для выбора области, GameViewport, результата, калибровки и диагностического кадра, а также копирует пиксели в массив для JumperVision и ArcadeVision. Захват сетки, Bubble и 2048 использует отдельный Accessibility takeScreenshot; PixelBoardLocator и GameOverScreen читают этот полный Bitmap. SceneRecovery преобразует источник пикселей и не устанавливает границы сам.

BoundedPixels — прототип чтения полноразмерного массива с границами и номером поколения. Это не контракт владения массивом и не защищает от повторного использования буфера другим потоком: до подключения ROI нужны неизменяемое владение кадром, идентификаторы сессии и поколения, проверка преобразования координат, отдельный полный кадр для результатов и диагностики, инструментирование всех читателей и отрицательные тесты. В текущем live pipeline он не используется; чтение вне ROI в нём ещё не защищено. Производительность не измерялась.

Для совместимости API на Java 17 CI использует --release 17 и полноценный JDK. Локальное отсутствие ct.sym нельзя прозрачно компенсировать source/target: они не ограничивают API целевой версии. tools/Compile.java не является общим раннером Verify, поэтому исправление только его не устранило бы ошибки всех тестов. Локальные прогоны без --release — диагностические, не эквивалент CI.
