# Проверка касаний и единый отчёт · 0.7.3 Dev

## Быстрая проверка на телефоне

При включённой Accessibility-службе откройте «Проверить касания» → «Начать проверку ×10». Программа сама привязывает только собственное тестовое окно, располагает компактную панель сверху и выполняет десять касаний движущейся цели. Подтверждением является прирост счёта на экране цели, а не один Android callback. STOP доступен во время теста. Старый запуск «Привязать» → «Демо ×10» сохранён.

Этот тест проверяет доставку касаний в собственную цель. Он не подтверждает распознавание и управление конкретной сторонней игрой.

## Один файл вместо нескольких логов

После неудачной попытки игры откройте LocalPilot → «Отчёт с кадром игры» → сохраните localpilot-diagnostic.zip. ZIP можно прикрепить в чат вручную.

Внутри находятся:

- session.txt: состояние до экспорта и последней активной сессии, профиль/приложение/геометрия, кадры/READ/решения/ввод/ACK, объекты и уверенность, ожидающее действие, подтверждённые ответы игры, результат демо и состояние повторного распознавания;
- device.txt: версия APK/Android, модель устройства, ABI, CPU/RAM/heap и подключение нашей службы; серийные номера и идентификаторы аккаунтов/сети не собираются;
- crash.txt: существующий отчёт Java/Android exit metadata;
- game-frame.png, если доступен: последний уменьшенный кадр только области привязанной игры;
- manifest.txt: наличие изображения, размеры и SHA256 каждого вложения.

Кадр сохраняется в RAM не чаще раза в секунду только при активной привязке к сфокусированной игре. В отчёте указан его возраст; кадр может быть старее последнего распознавания. Область за пределами игрового окна обрезается, overlay внутри окна может быть виден. При новом игровом профиле предыдущий кадр удаляется. При смерти процесса RAM-кадр исчезает, и экспорт честно отмечает его отсутствие. После переключения в главное окно прежний кадр не заменяется изображением LocalPilot.

Экспорт останавливает текущий ввод и использует снимок состояния, подготовленный до открытия системного выбора файла. Кодирование PNG/ZIP и запись выполняются в фоне. Запись или отправка изображения без нажатия кнопки отчёта не выполняется; облачный API здесь не используется. Изображения из пользовательского отчёта не добавляются в APK, исходники и Git автоматически.

## Пропавший ответ Android

Каждый жест получает собственный ID. Если Android не вызвал onCompleted/onCancelled за3с, watchdog снимает занятость и выдаёт ACK_TIMEOUT в действующей сессии. При STOP этот watchdog продолжает работать, поэтому отсутствие callback не блокирует последующий запуск навсегда. Запоздалый callback и таймер старого жеста не освобождают новый. При уничтожении службы ожидания отменяются. Завершение жеста по-прежнему не считается доказательством движения в игре.

В прежнем коде busy сбрасывался только в callback/ветке отказа dispatch. Сценарий отсутствующего callback является обнаруженным по коду риском; его связь с конкретным пользовательским отказом не установлена.

## Проверки и ограничения

19 JVM-проверок GestureFlight:таймаут, порядок completion/timeout, старые/чужие/повторные callback, смена жеста, STOP-подобное ожидание и сброс при уничтожении.21 проверка DiagnosticBundle:настоящий PNG, UTF-8, фиксированные имена, SHA256, отсутствие кадра и ограничения размеров/текста. Core total9677 assertions PASS.

Instrumentation дополнена запуском серии через видимую кнопку «Начать проверку ×10». Она компилируется, но без Android-устройства НЕ выполнялась. Фактический UI, Android callbacks, RAM-снимок, SAF-экспорт и управление реальными играми требуют проверки на телефоне. Успешная сборка не заменяет эту приёмку.
