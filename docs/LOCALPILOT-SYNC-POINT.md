## Кому и как синхронизироваться

- Все **новые** и **продолжаемые** чаты: сначала открыть Issue #159, эту страницу и актуальный `docs/LOCALPILOT-AGENT-HANDOFF.md`; затем прочитать реальный GitHub `main` SHA и последние CI/PR. Старый контекст считать историческим.
- Codex, Gemini и ChatGPT выполняют задачи в разных ветках и публикуют доказательства в едином Issue #159. Публикация комментария **не отправляет сообщения в уже открытые чужие чаты**.
- GitHub Actions собирает автоматические отчёты по доступным workflow, а `control_tower_dispatcher.py` обновляет один служебный комментарий. Нельзя считать отсутствие сообщения в другом чате отсутствием обновлений репозитория.
- Не создавать второй Control Tower, отдельный исполнитель игровых действий, декоративные кнопки моделей или не связанные с основным Harness игрушечные экраны.
- Стратегические модели советуют, компактные политики управляют через одного владельца действий; каждое действие подтверждается новым кадром/памятью игры и получает корректный результат либо UNKNOWN/STOP.

## Текущий ориентир

Checkpoint от 2026-11-15 снимал `main=fbbbeb9cb4ffa54ecc26582e4a640b963b80b8d3`. Это **только исходный ориентир**. При следующем запуске сверить SHA и состояние PR #168, #169 и Issue #99 с GitHub. Полный Android-тест 256 шагов на API35 эмуляторе PASS, **не** физический POCO. Rev9 Drive hardware twin только симулирован. G2 инференс реальной GGUF, G5 улучшение политики и G6 физический релиз ещё не подтверждены.

## Протокол нового checkpoint

1. Проверить живой `main` SHA, G0–G6 evidence, результаты on-device и все активные PR.
2. Опубликовать `docs/checkpoints/LOCALPILOT-CHECKPOINT-YYYY-MM-DD[-N].md` с ссылками на CI, точными APK/model/ROM SHA и честными PASS/FAIL/UNKNOWN.
3. Обновить **только эту ссылку** на новый checkpoint; оставить старый файл неизменным.
4. Синхронизировать те же факты в Issue #159 и Google Drive handoff.
5. Проводить изменения в работающем APK отдельно от изменения протокола координации. STOP, lease, TTL, epoch и визуальное подтверждение не ослаблять.

**Один исходный код, один управляющий контур, одна очередь принятия решений, разные места выполнения.**
