# LocalPilot Android 0.7.23-dev / code39

Исправлен подтверждённый дефект экспорта журнала. Добавлены данные, необходимые
для следующего разбора исчезновения панели; причина самого закрытия пока неизвестна.

## Что показывают присланные файлы

- Диагностика снята с 0.7.21-dev/code37, а не с 0.7.22.
- Оба файла audit ZIP имеют длину 0 байт. Диагностический ZIP читается без ошибок CRC.
- При экспорте служба Accessibility отключена; сохранённого Java-стека нет.
- Последние завершения Android: reason13=OTHER/status0. Это неопределённая причина,
  не доказательство low-memory kill или остановки пользователем.
- Значения памяти относятся к моменту экспорта, не к моменту прежнего завершения.

## Исправления

- Старый экспорт при отключённой службе читал только audit-v1.log и мог выдать
  сырые байты или пустой файл под именем ZIP, пропуская audit-segments.
  Новый AuditExport читает существующие сегменты и сохранённые legacy-источники
  независимо от состояния службы, не создавая писатель, не вращая и не меняя журнал.
- Перед экспортом через работающую службу ввод останавливается. Чтение и запись
  ZIP выполняются на фоновом потоке. Чтение файла защищено ограниченным по времени
  shared lock; цепочка SHA-256 проверяется до добавления в архив. При занятости,
  повреждении или превышении лимита выводится ошибка, исходник сохраняется.
- При отсутствии событий создаётся корректный ZIP со статусом no_journal_events.
  Это не доказательство успешной игры. Максимум восемь последних сегментов,
  два разных legacy-источника по 512 КиБ; размер ZIP ограничен 6 МиБ.
  Сегменты могут отражать разные завершённые моменты записи, это явно указано.
- Главный экран показывает версию установленного APK и различает разрешённую
  службу от фактически подключённой. При разрешении без подключения подсказывает
  выключить/включить службу в специальных возможностях без удаления данных.
- ApplicationExitInfo расшифровывает reason/importance, показывает PSS/RSS и
  ограниченный собственный маркер версии/фазы процесса (не более 128 байт).
  Допустимы только фиксированные фазы, размеры поверхности и известные типы ошибок.
  Произвольные описания Android, сообщения исключений и чужие маркеры не экспортируются.
  Android может отклонить обновление маркера; это не прерывает приложение и не
  гарантирует сохранение самой последней фазы. Старые запуски маркером задним
  числом не дополняются.
- Java crash metadata включает версию приложения на момент ошибки. Последняя
  фаза ошибки кадра сохраняется при STOP, вместо замены на общее CAPTURE_STOPPED.

Все операции локальные. Автоматической отправки, новых разрешений сети и новых
игровых контроллеров в этом выпуске нет. Исправления выбора механики и нагрузки
0.7.22 входят в APK. Пузырьки остаются неподдержанной механикой.

## Проверка на телефоне

1. Установить APK поверх предыдущего Dev-приложения; не удалять его данные.
2. Проверить в заголовке 0.7.23-dev/code39. Сразу выполнить «Экспорт журнала»:
   он доступен и без подключённой службы, ZIP должен открываться.
3. Если служба разрешена, но не подключена, выключить и включить LocalPilot
   в специальных возможностях. Затем выбрать окно браузера и механику игры.
4. Повторить сценарий. При исчезновении панели открыть LocalPilot и экспортировать
   диагностику сбоя, журнал и диагностический отчёт. Отправка — действие пользователя.

JVM-тесты, сборка и подпись описаны в docs/VALIDATION_0.7.23.txt.
Физический Android в этой среде не подключён; устранение исходного вылета
и прохождение игр на телефоне не подтверждены.
