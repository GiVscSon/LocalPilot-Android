# Приёмка Android 0.7.34: исследование 27 октября

База PR #8: 03a36f8, резервная копия сохранена вне репозитория.
API30: в run 40487871145 обе службы видели активное окно после таймаута;
конкретная причина отсутствия строки во время выбора не установлена. В тесте
добавлена bounded трасса окон, идентификаторов, состояния сессии и диалога.
API35: run 40488255281 показал перекрывающий окно системный диалог Quickstep
isn't responding; это не доказательство неисправности кнопки приложения.

Run 40493144009 на c42fa4e: PASS API30/35/36, один прогон. Run 40492997968
на 99f3444 и 40493325255 на 38af7a3: FAIL API30 в Bubble, fixture принял
жест, прогнозируемое поле совпадало, но Android ACK около 5 секунд и два
своевременных стабильных кадра не получены до истечения защитного срока.
API35/36 проходят в указанных прогонах; причины пятисекундной задержки ещё
не доказаны. Таймаут визуального подтверждения не увеличивался.

Обнаружен отдельный дефект: запоздалый callback мог обойти watchdog, ожидающий
в той же очереди главного потока. Исправление 3dfdb9f проверяет истечение
срока внутри callback; устаревший жест не подтверждается и контур останавливается.
Добавлены отрицательные JVM-тесты; Verify и Android-компиляция PASS. Для поиска
блокировки в инструментальном тесте добавлена bounded трасса долгих сообщений
главного потока. Полный JVM-набор и релизные тесты ветки до этой небольшой
правки прошли; GitHub build для 3dfdb9f PASS, device acceptance 40494232772 и
40494392203 для 3709ed0 показал FAIL API30: после второго реального касания сработал ACK_TIMEOUT; API35/36 прошли. Instrumentation зарегистрировала несколько последовательных сообщений HandlerCaller по ~5 секунд. Run 40495078900 на 0067568 зафиксировал главный поток внутри Android AccessibilityCache.onAccessibilityEvent (до callback LocalPilot), а не доказал причину в игровой логике. Run 40495711435 на e11993e показал на потоке UiAutomation ожидание findAccessibilityNodeInfo при refreshCachedNodeLocked для TYPE_WINDOW_CONTENT_CHANGED, пока главный поток ждёт тот же AccessibilityCache. Ограничение подписки тестового UiAutomation в 8ba11e1 оказалось недостаточным: run 40496679111 на 3365568 вновь получил тот же стек и ACK_TIMEOUT. Ограничение отменено; надёжное исправление блокировки пока не доказано.

Физический Android и три последовательных полных Android matrix на одном SHA:
NOT RUN / НЕ ПОДТВЕРЖДЕНО. Никакой стабильный релиз не заявлен. Для
продолжения: изучить свежие device результаты и slow-main trace; устранить
источник задержки без обхода визуальной проверки, повторить полный набор и
три матрицы на одном commit, затем проверить физический телефон.
