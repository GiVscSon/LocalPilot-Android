# LocalPilot Android 0.3.0 — локальные CPU-авторежимы трёх игр

Android 11+, без ПК, облака и root во время работы. Это экспериментальная APK с разработческой подписью и отключённой отладкой: сборка и подпись проверены, физический телефон пока не подключался.

## Новые игры и защита
В главном меню появились «Крестики-нолики» и «Погаси свет». Открыть игру → на панели Привязать → Выбрать поле (квадрат3×3 или5×5) → Крестики авто/Свет авто → сверить матрицу → подтвердить ввод.
Крестики:0 пусто,1 X агента,2 O соперника; minimax с memoization, не больше9касаний/60с. Соперник стенда выбирает случайное свободное место.
Погаси свет:0 выключено,1 включено; касание меняет клетку и её ортогональных соседей. Решение GF(2), до25касаний/60с. Стенд генерирует решаемые поля. Это узкие профили наших встроенных игр; сторонние крестики/лампы не подключены.
Во всех трёх профилях используется снимок, а не скрытый доступ к массиву игры, и один прежний executor. Перед каждым шагом — актуальное окно/ROI, после — отдельная проверка исхода.

Привязка теперь оставляет ввод выключенным. Для ручного режима нажать «Разрешить ввод» и подтвердить до40жестов/2мин; авторежимы выдают своё ограниченное разрешение только после проверки матрицы. Stop отзывает его. Разрешение на конкретный dispatch одноразовое и связано с выдавшим ActionGate: повтор/другаяauthority отвергаются.

Журнал audit-v1.log хранится в private app files, без кадров, текстов, координат, package names или игровых матриц. PROPOSED записывается с fsync перед вводом, Android completed/cancelled и отдельный VERIFIED_2048 различаются. Late ACK связан с исходным epoch. Checksum chain/restart readback/размер≤512KiB; повреждение, заполнение или ошибка записи блокируют новый ввод, исходный файл не чистится. Это обнаружение повреждений, не криптографическая аутентификация против root/подмены всех хэшей. Журнал не является PPO trajectory store. Экспорт через системный выбор файла в главном меню останавливает ввод; при повреждении допускается сырой forensic export без восстановления управления. Полный snapshot/restore учебных данных здесь не реализован.
APK не запрашивает INTERNET/storage permissions, backup выключен, cleartext запрещён, в поставляемой APK debuggable=false. Service экспортирован только с обязательным BIND_ACCESSIBILITY_SERVICE; остальные игровые Activity не экспортированы. Root, другая accessibility-служба, аппаратные сбои и уже переданный жест находятся вне гарантии нашего gate.

## Первый запуск
1. Установить LocalPilot_Android_0.3.0_signed.apk. Подпись сохранена от нашей 0.1.1, поэтому штатное обновление должно приниматься Android. Принятие обновления на устройстве ещё не проверено.
2. Открыть LocalPilot → специальные возможности. При обновлении выключить/включить службу LocalPilot, чтобы Android прочитал новую capability получения снимков. Разрешение пользователь включает самостоятельно.
3. Нажать «Открыть 2048». Это встроенный видимый стенд без скрытого доступа политики к полю: автоконтроллер читает screenshot и отправляет обычные свайпы.
4. На панели «Привязать» → «Выбрать поле». Обвести квадрат игрового поля от внешнего верхнего левого до внешнего нижнего правого края, без заголовка и счёта. В верхней зоне экрана можно отменить выделение.
5. Нажать «Авто2048». Приложение получает два снимка в RAM и показывает распознанные 16 клеток. Сверить их с игрой. Только если все клетки совпали, нажать «Поле верное, начать».
6. Авторежим ограничен 20 ходами/60 секундами. Панель сворачивается, STOP остаётся. Если она закрывает поле, передвинуть её, снова привязать и выделить поле.
7. Проверить Stop во время/между свайпами, смену приложения, поворот, блокировку экрана и отключение службы. Уже переданный Android жест до 120 мс может завершиться после Stop. Новые наши задания и продолжения callback отзываются по epoch.

Для сторонней 2048 порядок тот же, но поддерживается только классическое квадратное поле 4×4 и палитра оригинальной 2048 (от пустой клетки до 2048). Другие темы, night mode, прозрачность, реклама поверх поля и анимации могут вызывать UNKNOWN/Stop. Это ожидаемый отказ, а не повод ослаблять пороги. Не обещается управление всеми играми. Не запускать другой ADB/autoclick executor одновременно.

## Как работает
Screenshot AccessibilityService → строгая известная палитра, по 3 точки на клетку → две одинаковые матрицы из независимых захватов → маска легальных ходов → детерминированная CPU-эвристика → единственный dispatchGesture → новые снимки → проверка результата стандартных слияний и ровно одного spawn 2/4. Если результат иной, дальнейшего ввода нет.

Проверяются package/window/geometry, Stop epoch, запрос и монотонный timestamp снимка (uptime отдельно от elapsedRealtime), TTL700 мс, положение панели. Одинаковое содержимое двух независимых кадров допускается: игра может быть неподвижной. Повтор одного timestamp отвергается. На Android30 между запросами оставлена большая пауза; при системной ошибке захвата — Stop. Отображаемые «кадр/CPU мс» — последние локальные измерения телефона, не опубликованный FPS/p95. Изменение изображения само по себе не является наградой.

Снимки всего дисплея временно появляются в RAM для выделения ROI, но не сохраняются и не передаются. Приложение не имеет INTERNET permission. Матрицы/планы/обучающий опыт после закрытия не сохраняются; отдельно остаётся только журнал метаданных исполнения. Долговечный обучающий журнал ещё не подключён.

## Что перенесено из PPO-бота
Прочитаны PPO_LEGACY_MERGE_2026-10-16.ru.md и CODEX_HANDOFF_PPO_2026-10-16.md. Отдельный исходный SKILL.md старого Universal PPO Bot и проверенные старые веса не найдены. Память чатов не объявлялась исходным кодом.
Verified2048 задаёт feature schema grid2048-exponents-v1, action vocabulary left-up-right-down-v1, policy cpu2048-heuristic-v1, маску действий и проверяемую merge reward. Награда выведена из распознанных до/после матриц и стандартных правил: это не независимый OCR официального счёта и не гарантия причинности при вмешательстве пользователя. ppoEligible=false: здесь нет old_log_prob/critic/current-policy rollout. Это эвристический baseline, не PPO и не обучение весов.

Следующий настоящий PPO-этап: durable verified transition storage с readback/ACK, независимые проверки зрения и награды, среда обучения с parity, отдельный train/play, frozen on-policy rollout с policy_id/old_log_prob/value, корректные termination/truncation и GAE. Игровых duration_frames у скриншотов Android нет — нельзя подставлять в GAE выдуманный frame clock из wall time. Потом независимый holdout и Shadow перед разрешением новой политике отправлять предложения этому же executor. Текущий Windows checkout не тронут.

## Реальные проверки
- 13 compiled ActionGate assertions PASS; дополнительно2634 hardening/mini-game assertions: replay,issuer,permit expiry/budget,fsync/reopen/truncated journal,50CPUпартий крестиков без поражений случайному сопернику,100solvableLightsOut. Это синтетические проверки логики, не device gameplay.
- 6131 compiled board/reader/freshness/parity assertions PASS: правила слияния, отсутствие каскада, неизвестные цвета, маски, invalid spawn, conservation, 500 случайных полей.
- В их числе cross-language parity: 200 полей × 4 направления, итоговая матрица и reward совпадают с localpilot/game2048.py из исторической v0.3.1.
- Все Java исходники скомпилированы против Android API35; aapt2/d8/zipalign/apksigner v3 PASS.
- НЕ проверены: установка, реальные Android screenshot/gesture callbacks/Stop races, сторонняя игра, качество решения и победы, телефонная latency/нагрев/батарея. Синтетические RGB-тесты не доказывают качество на реальном screenshot. Встроенный стенд также ещё не запускался на устройстве.

# Android 0.3.2 — 20 октября 2026: подтверждённые примеры
ExperienceStore: versioned symbolic transition schema LOCALPILOT-EXPERIENCE-v1; profile2048/ttt/lights; before/after/action/derived merge reward2048, reward0 дляmini, ppo=false. Профили используют текущие правила Board2048/MiniPolicy и row schema v1; это не универсальные observation/action spaces. Сбор только после отдельного согласия кнопкой; по умолчанию выключен, разрешение не сохраняется после пересоздания службы. При включении Stop; требуется новая привязка/разрешение ввода. Обычный Stop прекращает действия, сбор остаётся включён для следующего явно разрешённого раунда; выключение сбора отдельной кнопкой. Кадры не сохраняются.
После прежнего Android callback и двух стабильных распознанных полей loop проверяет переход, затем записывает. Это подтверждение symbolic rules при условии корректного зрения, не независимое доказательство исхода/полный training rollout. Нет timestamps/logprob/value/model weights/training/автоподключения JEV.
Private app file experience-v1.log; предел256строк/256КиБ; SHA256chain и semantic revalidation на открытии/export/import; отдельный FileLock, полный новый snapshot во временныйфайл+FD.sync+ATOMIC_MOVE. При unsupported atomicmove операция отказана, fallback не используется. Нет auto-clear/rotation/salvage. Corrupt/full/writefailure при включённом сборе →stop+сборoff, существующий файл сохраняется. Импорт целиком проверяется и разрешён только в пустое исправное хранилище, не сливает/не заменяет существующие примеры; import ввод/сбор выключает. Экспорт через SAF останавливает ввод. Atomic move не доказывает power-loss durability каталогов/накопителя; аварийное отключение Android не проверено. Hashchain не аутентификация: импортированный файл может быть самостоятельно пересчитан; не доверять для обучения автоматически. Скопированные pendingfiles после аварии могут остаться, автоматически не импортируются.

ПолнаяJavaAPI35/aapt2/d8/zipalign/apksignerV3 PASS; Android0.3.2/Gradle/lint/CI/device powerloss не проверены.
