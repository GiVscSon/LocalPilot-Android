# LocalPilot Console AI Lab · единая архитектура

Статус: обязательная спецификация нового направления, **не отчёт о реализованном автономном агенте**.

## Решение владельца (12 ноября 2026)
- Убрать симуляторы мини-игр Яндекс Маркета из пользовательского сценария; они не должны быть источником метрик качества агента. Legacy-код и старые CI сохраняются до отдельного безопасного удаления, но не предлагаются как основная лаборатория.
- В одном Android APK: консольные эмуляторы + ModelLab + агентный runtime + журнал экспериментов. Ни один модуль не должен существовать только как декоративная кнопка.
- Начать с NES/Денди (JSNES реально исполняет ROM), далее добавлять только проверенные консольные ядра через общий адаптер. DOS сейчас **не** эмулируется: только проверка форматов.
- Локальные GGUF загружаются по выбору. Наличие модели в каталоге **не** означает её пригодность для управления или поддержки vision.

## Единый цикл агента (целевой контракт)
1. **ConsoleAdapter.observe()**: кадр, epoch/session, счётчик кадров, состояние контроллера, доступные кнопки и свежесть. Не выдавать кадр за reward.
2. **ModelRuntime.infer()**: выбранный GGUF или policy, явные вход/выход, CPU/Vulkan capability и latency. Vision требует реально загруженных model + mmproj. Для текстовой модели нужен структурированный state extractor, а не выдуманное зрение.
3. **ActionParser**: строго ограниченная схема: `{button: UP|DOWN|LEFT|RIGHT|A|B|START|SELECT|NONE, frames: 1..30, session, observationId}`; свободный текст не превращается в нажатия. Неправильный JSON, таймаут, старый кадр => STOP.
4. **ActionGate**: пользовательский запуск, только текущая ROM-сессия, один исполнитель, bounded duration, STOP с высшим приоритетом, TTL, запрет выполнения при смене окна/ROM. Никаких прямых Android Accessibility-жестов от модели.
5. **ConsoleAdapter.act()**: исполнение внутри локального эмулятора с подтверждением реального отпускания кнопки.
6. **Verifier**: **новый** кадр после действия, подтверждённая смена состояния, score/reward только если измерим. ACK эмулятора не равен успеху.
7. **EpisodeStore**: observation/action/verification/reward, versioned schema, provenance, ROM fingerprint, model ID + SHA256, backend, тайминги, причина STOP. Обучение на эпизодах возможно только отдельным проверенным алгоритмом, не по факту записи.
8. **UI**: один экран с выбором ROM, модели, CPU/Vulkan, Start/Pause/STOP, live status, episode timeline, ошибками и результатами. Если нет модели, покажи `MODEL_NOT_READY`; если Vulkan не собран/не доступен, `GPU_UNAVAILABLE`, без фиктивного GPU-режима.

## Реальное состояние к этому коммиту
- NES WebView работает; есть ручное управление и ограниченный CPU homebrew-тест.
- NES передаёт ModelLab эпизод и PNG, ModelLab может описать изображение с vision GGUF. **Обратной дороги model -> console input пока нет.**
- Vulkan-native функции присутствуют в исходниках, но сборка единого APK и фактическое выполнение на GPU ещё должны быть подтверждены.
- В PR изменена только навигация главного экрана: вход в консольную библиотеку вместо старых симуляторов. Остальной контракт выше **план и критерии приёмки**.

## Приёмка
- На одном SHA: тест навигации Main -> RetroLibrary -> NES -> ModelLab, без второго APK.
- Настоящая ROM, настоящие кадры и действия: не менее 20 циклов observe/infer/act/verify, доказуемые fresh frame + STOP.
- Сравнить CPU и Vulkan на одном GGUF, измерить latency/память/число токенов; GPU считать работающим только при подтверждённом backend + device runtime.
- Любой неизвестный/неподдерживаемый формат ROM или модель => понятный отказ, не фиктивный запуск.
- Физическая приёмка POCO X7 Pro отдельно от CI. Не называть debug APK стабильным релизом.
