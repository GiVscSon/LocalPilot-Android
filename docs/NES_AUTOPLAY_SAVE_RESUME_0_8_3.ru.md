Проверяемый пользовательский путь в одном APK:
Harness Console → «Автоигра Student ·256 ходов с сохранением» → существующий
JSNES + тот же HarnessCoordinator → 16 подтверждённых шагов → durable replay →

серия. После остановки процесса: Harness Console → «Продолжить сохранённую автоигру».
Эти маршруты доступны и из ModelLab, и непосредственно в NES.

## Что сохраняется

NesSaveStore сохраняет один локальный слот latest.nss: исходные байты ROM и их SHA256,
полное состояние JSNES CPU/PPU/mapper/audio/controllers, номер и hash видеокадра,
режим NES/Денди, счётчик подтверждённых действий и SHA политики. Размер ограничен;
запись выполняется в отдельном IO-потоке через fsync + atomic rename и checksum.
WebView передаёт JSON состояния порциями до64KiB в обе стороны с отдельным
токеном/смещением и отменой по STOP; большой граф CPU/PPU не отдаётся целиком
через стандартное преобразование JavaScript-объектов Android.
Повреждённое сохранение не перезаписывается молча. Частные ROM и состояния не
выгружаются в Git или сеть.

Сохранение снимается только на неподвижной границе без удерживаемых кнопок и
выполняющегося действия. При восстановлении проверяются ROM/core/frame/hash,
создаётся новая эпоха, все кнопки отпускаются. Старые tickets, permits, callback,
таймеры и право на ввод не сохраняются. Изменённая политика не может молча
продолжить старую автоигру. Само открытие приложения не запускает ввод: необходимо
явно нажать продолжение. Ручное сохранение при активной серии просит остановиться
на следующей записанной границе; STOP остаётся немедленным.

## Границы готовности

- Автоигра ограничена256 действиями за явно запущенный сеанс (16серий×16шагов),
  без увеличения TTL/дедлайнов жестов и обхода STOP. Каждая серия использует
  свежие RAM/кадры и общий контроллер; счётчики интерфейса не заменяют выполнение.
  Маска зависит от текущих координат RAM: движения, пересекающие8-битный край
  при данном бюджете кадров, не предлагаются политике. Маска сохраняется вместе
  с oldLogProb; проверка награды не ослаблена. Статусы обновляются не чаще раза
  в2секунды во время автоигры, STOP/ошибки — сразу; высота статуса фиксирована.
- Автоигра Student пока предназначена только для встроенной проверенной NES-ROM.
  Это действительная6502/PPU-эмуляция. Для произвольных импортированных ROM остаётся
  ручная игра с сохранением/загрузкой; достоверной универсальной награды/политики нет.
- PPO создаёт настоящего кандидата, но новый кандидат не перезаписывает предыдущий
  ожидающий экзамена. При существующем валидном кандидате следующие эпизоды
  сохраняются без нового обучения. Активные веса и ожидающий кандидат не меняются.
  Независимый экзамен и доказанное улучшение политики ещё нужны; непрерывное
  обучение с автоматическим продвижением здесь не заявляется.
- Сохраняется последняя успешно записанная16-шаговая серия. При аварийном завершении
  неполная текущая серия может быть потеряна. RNG выбора действий не сохраняется:
  CPU/PPU продолжается с точного состояния, будущая случайная последовательность
  действий не обязана повторяться.
- Локальные журналы и replay имеют прежние ограниченные размеры. При заполнении
  агент останавливается с требованием экспорта, не удаляя пользовательский опыт.
  Старый RAM-журнал допускает256записей суммарно, поэтому существующая история
  может остановить автоигру раньше бюджета. Автоматическая ротация этого журнала
  и пользовательский bulk-export ещё не подключены.
- GGUF путь по-прежнему ограничен4 ходами. Его наличие не означает GGUF fine-tuning,
  GPU-ускорение или готовность всех четырёх подсистем для любых игр.

## Проверки

Локально: настоящий JSNES исполнил40 действий, затем сохранение перенесено в
новый экземпляр страницы; следующие7 одинаковых действий дали идентичные RAM и
пиксели непрерывному исполнению. Новая эпоха, отсутствие удержаний/автозапуска,
отказ чужой эпохе и повреждённому framebuffer проверены. Android bridge в этом
Node-тесте моделируется — это не Android-приёмка.

```sh
java tests/NesSaveStoreVerify.java
node tests/nes_save_resume_smoke.cjs PATH_TO_VERIFIED_JSNES PATH_TO_BUILTIN_ROM
python3 -m unittest discover -s tests -p test_nes_autoplay_resume_acceptance.py -v
```

Расширена существующая Android API30/35/36×phone/tablet матрица одним новым
сквозным тестом tools/nes_autoplay_resume_acceptance.py: фактические UI-кнопки,
минимум32автоматических действия, файл CPU/PPU, STOP, force-stop процесса,
повторный запуск, продолжение именно с сохранённого кадра, новые replay,
неизменность активных весов/кандидата. Он не подменяет вход нажатиями ADB по игре;
игровые действия выполняет production Harness. Результат нового CI требуется
подтвердить; прежний зелёный CI не распространяется на новый кандидат.
Физическая приёмка NOT_RUN, stable release_ready=false. Для APK использовать
уже созданный новый постоянный signer; не генерировать ещё один ключ.
