# API 36: сохранение подтверждённого выстрела при отмене следующего плана

## Наблюдение и воспроизведение

База: `91b1a15244a6f88b434eff42552ddae15cebb150`, PR #25.
Третий полный прогон — run `40769222867`, attempt 2: API 30 и 35 PASS,
API 36 FAIL в `checkBubbleScreenshotProgress(true)`. Это падение не было
`SCREENSHOT_TIMEOUT`: итоговая ошибка — отсутствие визуального подтверждения
выстрела, а единственная CAPTURE-ошибка — `STALE_BEFORE_DISPATCH`.

Независимая синтетическая фикстура приняла один рикошет, удалила три исходных
оранжевых шара и оставила 16 шаров. JVM-воспроизведение на области 1038x1479
подтверждает этот результат. Координаты последнего жеста из лога, локальные
`177,392`, и прогноз 8 оставшихся шаров относятся уже к следующему жёлтому
выстрелу, а не к неверно рассчитанному первому рикошету.

`bubbleStep` подготавливал следующий план через `sent`, но если повторная
проверка свежести внутри `sendObserved` отклоняла отправку, вызывал полный
`reset()`. Это стирало уже полученный `verified_shots=1`. Проверка приёмки
пропускала доказанный первый успех и ожидала результат следующего выстрела
от фикстуры, которая намеренно принимает только один.

## Исправление

- `cancelUnsent()` удаляет только подготовленный неотправленный план, сохраняя
  предыдущие подтверждения и диагностические счётчики. После отмены нужны два
  новых устойчивых кадра; уже использованный кадр не принимается повторно.
- Сервис вызывает отмену только при неизменившемся `captureSent`, который
  увеличивается синхронно после принятого `dispatchGesture`. При полученном ACK
  отмена плана запрещена. STOP и явный новый сеанс сохраняют полный `reset()`.
- Новая регрессия воспроизводит точные размеры проблемной области. Замена
  отмены на прежний `reset()` ломает проверку сохранения подтверждённого результата.
- Отдельно обновлены устаревшие ожидания `CaptureMatrixTest`: текст ожидания
  согласия и существующие дедлайны SERVICE/FIRST_FRAME по 15000 мс. Production
  дедлайны не менялись. Раннер добавлен в JVM CI.

## Границы вывода

Локальный прогон исправленного дерева, OpenJDK 21.0.2 с полным `ct.sym`:
все 22 `tests/*Verify.java` PASS; release tooling 10/10 PASS;
`build_debug.py` с Gradle 8.9, SDK 35/build-tools 35.0.0 PASS, включая
`assembleDebug`, `lintDebug`, `compileDebugAndroidTestJavaWithJavac`.
`CaptureMatrixVerify`: 223 сценария, 464 утверждения PASS.
Существующие настройки `--release 17` не ослаблялись.
Эмулятора/KVM в локальной песочнице нет. Локальный APK подписан новым тестовым
ключом песочницы, совместимость с подписью установленного APK не установлена.

Подтверждены причинная регрессия JVM и независимая проверка точного первого
рикошета. Новый Android-прогон необходим: локальные тесты не заменяют приёмку
API 30/35/36 и физического телефона/планшета. Прежний периодический
`SCREENSHOT_TIMEOUT` из issue #24 остаётся отдельной открытой проблемой.
Тайм-аут скриншота 4000 мс, executor callback, проверка точного результата,
ActionGate, InputPermit и подпись установленного приложения не изменены.
