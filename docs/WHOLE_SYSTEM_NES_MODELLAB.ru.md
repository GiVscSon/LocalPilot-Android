# Единая сквозная система: игровые агенты, GameLab/NES, ModelLab и LocalPilot

## Компоненты и границы
- **LocalPilot**: отдельное игровое приложение, CPU-решения для 10 игр, компьютерное зрение, реальный Android ввод только через ActionGate, InputPermit, STOP, TTL и независимое подтверждение кадром. Не импортирует слова LLM как жесты.
- **GameLab**: отдельный NES/Денди JSNES 2.1.0 (проверенный Apache-2.0), оригинальный 6502 homebrew NROM и автоматический CPU-агент для **homebrew A**. Агент удерживает A 16 **реально отработанных** кадров (не миллисекунд) и выпускает кнопку. На пользовательском ROM кнопка CPU-агента запрещена. Результат виден только после нового кадра.
- **ModelLab**: отдельный APK с постоянным ID `org.localpilot.modellab`, импортом GGUF и локальными текстовыми/визуальными моделями. Не имеет Accessibility и права игровых жестов. Получает NES-эпизод в Android Intent по одному нажатию пользователя, анализирует его выбранной моделью также по одному нажатию. Нет прямого доступа к ROM или эмулятору.
- **Общий контракт** `org.localpilot.shared.NesTrial`: один schema-id, JSNES, сценарий HOMEBREW/USER_ROM, кнопка, номера двух **реальных** кадров, хеши изображения и вычисленный статус `PIXELS_DIFFER` либо `NO_VISUAL_CHANGE`. SHA-256 обнаруживает повреждение, **не удостоверяет источник** и **не доказывает причинность, победу или счёт**.

## Сценарий воспроизводимого теста на устройстве
1. Установить отдельные APK GameLab и ModelLab. На NES-экране GameLab запустить оригинальную тестовую игру.
2. После получения кадров нажать **«CPU NES-агент · тестовый ход A (16 кадров)»**, либо вручную A. В самой игре A меняет фон, а реальные кадры и пиксели сохраняют свидетельство.
3. Нажать **«NES → ModelLab · передать проверенный эпизод»**. Отправляются только ограниченные счётчики, имя кнопки и контрольные хеши. ROM и изображение не передаются.
4. В ModelLab выбрать встроенную либо импортированную GGUF и нажать **«Объяснить последний NES-эпизод выбранной нейросетью»**. Модель получает лишь безопасный текст с ограничениями свидетельства. Быстрые движения и весь игровой ввод остаются у CPU.
5. Для анализа изображения вручную выбрать фотографию или скриншот, только с парой vision GGUF + подходящий mmproj. Прямой захват чужого окна по умолчанию отключён.

## CI gate
`.github/workflows/whole-system-acceptance.yml` на **одном SHA**: SHA-512 npm jsnes, исполняемый NES CPU/PPU, оригинальный домашний ROM, эмулированная кнопка с изменением пикселей, JS→JVM контракт NES, tamper/fake rewards rejection, CPU selfplay 10 игр, policy безопасности импорта, сборка трёх разных Android APK, их фиксированные идентификаторы, подписи и подтверждение, что ModelLab не имеет игровых разрешений.

Кроме этого, `nes-runtime.yml` запускает узкий E2E контракт. Результаты CI нельзя выдавать за проверку Android Intent на физическом POCO X7 Pro. Для окончательной приёмки нужно ещё реально нажать передачу и сравнить работу хотя бы двух моделей; снимки пользовательских ROM без согласия не сохраняются.

**Известные ограничения:** CPU-агент на homebrew проверяет однокнопочный ход, не обучает самостоятельно все NES-игры. Хеши не идентифицируют объект и не являются наградой. Импорт GGUF не гарантирует, что движок поддержит архитектуру. Компактная версия ModelLab не содержит предустановленных весов.

## Лабораторное отключение автоматической остановки
В NES-экране GameLab появился флажок **«Лаборатория NES: игнорировать авто-STOP при неизменном кадре»**. Он доступен только на оригинальном встроенном homebrew-картридже и имеет смысл при запуске **серии до 5 действий CPU-агента**.

В обычном режиме серия останавливается, если после шага `NO_VISUAL_CHANGE`. В экспериментальном режиме этот случай регистрируется как ошибка, но допускается следующий шаг, чтобы собрать диагностические данные. Режим не делает ошибку успешным результатом.

**Нельзя отключить:** ручную кнопку STOP, отпускание удерживаемых кнопок, STOP при уходе приложения в фон, проверку подтверждения ввода, ограничение ожидания кадра, жёсткие 5 шагов, отказ на пользовательских ROM и любые защиты реального LocalPilot (ActionGate, InputPermit, TTL). Переключение флажка в активной серии прекращает её, чтобы режим не изменялся незаметно.


## Настоящие NES-ROM из открытых источников

GameLab уже выполняет настоящие `.nes`-картриджи в JSNES 2.1.0 (CPU 6502 + PPU), не подменяя их игровыми симуляторами. `Выбрать картридж (.nes)` импортирует пользовательский ROM через системный Android-пикер и проверяет заголовок iNES/NES2; поддержка конкретной игры зависит от её mapper и точности ядра.

Новая кнопка **«Скачать и запустить VOID LANCER · MIT · 41 КБ»** загружает полноценный авторский homebrew-картридж [VOID LANCER v1.0.0](https://github.com/Riyoway/void-lancer-nes/releases/tag/v1.0.0) с прямого pinned release URL, проверяет размер 40 976 байт, SHA-256 `5eb801aca68131a3d17fa82d8901d46f6098b878d1e00cd1c47d00c001c2405a`, проверяет iNES и сохраняет в приватном каталоге для следующих офлайн-запусков. При неуспешной проверке файл не запускается. Лицензия автора MIT, исходники в том же репозитории.

Кнопка **«Каталог бесплатных homebrew NES-ROM»** открывает внешний сайт [itch.io](https://itch.io/games/free/tag-homebrew/tag-nes-rom), где можно выбрать другие авторские игры, скачать их через браузер и открыть из файлов. Не скачивай коммерческие игры без законного права на копию; приложение не содержит каталог нелицензированных ROM. Сеть в GameLab используется только при явной загрузке, WebView самого NES-ядра остаётся без сетевого доступа.

**Реальный ROM и реальный автономный игровой агент не равнозначны.** Пальцевые кнопки и ручная регистрация эпизодов действуют на пользовательских играх. Автоматическая серия действий CPU-агента по-прежнему разрешена только во встроенном homebrew, пока не проверены распознавание состояния, награда и STOP для конкретного стороннего ROM. ModelLab получает только bounded evidence, а не полномочия Android-ввода.

Новый whole-system тест извлекает именно авторский ROM из GitHub release, сверяет SHA-256, прогоняет его через настоящий JSNES и отдельно проверяет политику загрузки GGUF. Для физической приёмки необходимо открыть ROM на POCO X7 Pro, нажать START/A, убедиться в смене реальных кадров и передать эпизод в ModelLab.
