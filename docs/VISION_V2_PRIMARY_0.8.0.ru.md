# LocalPilot-Android 0.8.0 · Vision V2 — основная линия развития

**Версия:** `0.8.0-dev-install1080` / `versionCode 52` / `org.localpilot.android.dev.install1080`.

**Архив прежней основной версии:** `archive/localpilot-android-0.7.35-before-vision-v2-20261104`
(коммит `cae9ae2123cd5892195e0279183a1e939f71caea`).

Предыдущая версия может оставаться установленной параллельно: новый debug applicationId отличается. Важно, что Android AccessibilityService и разрешение MediaProjection для двух пакетов настраиваются отдельно.

## Почему вводится Vision V2

Задача пользователя: старое распознавание, основанное на постоянных цветах или единичном кадре, неустойчиво на реальном телефоне и планшете. Новый основной слой строится **над реальными последовательными пикселями**. Он должен охватить все десять игровых профилей, но не объявлять обучение или правильные ходы на основании анимации.

Ссылка на исследование NitroGen: https://nitrogen.minedojo.org/ · https://github.com/MineDojo/NitroGen · https://huggingface.co/nvidia/NitroGen

NitroGen — опубликованная vision-to-action модель для видео и gamepad. **Она ещё не встроена в APK**: оригинал построен для Windows/gamepad (SigLIP2+DiT, около 493 млн параметров, 256×256 RGB → 21-step gamepad-команды); наша задача использует Android touch жесты и отдельные механики мини-игр. Перенос требует квантования/адаптера и физической проверки. Ролики Trackmania/Cuphead полезны как обучающие примеры, но воспроизведение их необъявленных checkpoint не заявляется.

## Что реально изменено в 0.8.0

- `VisionV2Core.java`: общая ограниченная пиксельная память из **48×64** точек на ROI. Изображение обрабатывается на устройстве и **не отправляется в сеть**. Каждый кадр сопоставляется с предыдущим по времени, границам ROI, исключённой области STOP, источнику (MediaProjection или Accessibility) и эпохе ActionGate.
- Устойчивое к общей экспозиции сравнение яркости плюс разности цветовых компонент. Пороговые локальные изменения объединяются в связные компоненты (до 12 прямоугольников движения), без утверждения о том, какие это объекты.
- Replayed/старые кадры и разрывы более 850 мс не дают кадру статус READY. Смена области, фокуса, окна, сессии и STOP сбрасывают историю. Два согласованных кадра требуются для нового движения.
- `PilotService`: все снимки системного Accessibility захвата (2048, сетка, Шипучка) наблюдаются Vision V2; недостаточно открытая ROI после маскирования STOP отклоняется.
- Реальные кадры MediaProjection (Ари, Карканоид, Маркет Раш, Гошан) проходят Vision V2 до существующего детектора. **Ни один объектный вывод старого детектора не передаётся контроллеру до READY от Vision V2**.
- `exportMetrics()` теперь сохраняет в диагностике **метаданные** состояния Vision V2 перед STOP. Кадры не добавлены в диагностический журнал.
- Новые JVM-регрессии `tests/VisionV2Verify.java`: движение объекта, сдвиг экспозиции, защита от replay, маска STOP, смена ROI и epoch, потеря кадров.

## Как это соединяется с обучением

Главный цикл развития:

```
свежие сырые кадры
  → Vision V2: пиксельные изменения + временные объекты
  → распознавание семантических объектов и правил конкретной игры
  → WeightSpace / игровая стратегия
  → ActionGate + InputPermit + STOP + TTL
  → dispatch → Android ACK → отдельный новый кадр
  → game-specific visual witness → replay / обновление совместимых весов
```

**Пиксельная разница сама по себе не является наградой:** меню, вспышка и движение рекламы тоже изменяют экран. Игровой свидетель остаётся предметным (шар изменил траекторию, фишки достоверно перестроились, число 2048 объединилось, герой поднялся). UNKNOWN никогда не получает выдуманную метку.

### Честное ограничение

Это **первая интегрированная версия нового общего зрительного ядра**, а НЕ заявление, что полноценная универсальная NitroGen обучена для всех десяти игр. Существующие игровые классификаторы пока продолжают устанавливать семантическую личность объектов. Следующий этап: обучаемый object detector/embedding и согласованные видео→действие модели для каждого профиля, при обязательном сопоставлении с реальными кадрами.

Старые игровые контроллеры сохранены в архиве и временно используются как проверяемые специальные декодеры/резерв при невозможности распознать новую сцену, но разработка новых функций должна идти через Vision V2 + WeightSpace.

## Приёмка

- JVM + Build + Android unit/lint + API 30/35/36 должны завершиться PASS **на одном HEAD SHA**.
- Подпись и точный applicationId APK отдельно проверяются. Старый и новый APK не должны перезаписывать друг друга.
- Issue #69 остаётся открытым до **10 игр × 2 реальных устройства × 5 подряд визуально подтверждённых действий** на каждую игру.
- `PANEL_COVERS_ROI`, `CONSENT_TIMEOUT`, потеря фокуса, `protected-skull SWAP_MATCH3` и `UNKNOWN` требуют собственной проверки. Android ACK **не** означает, что игра ответила.

Финальное слияние в `main` не равняется готовому стабильному релизу; релиз проверяется реальной полевой матрицей.
