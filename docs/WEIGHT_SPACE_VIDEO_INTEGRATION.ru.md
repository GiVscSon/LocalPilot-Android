# Weight-space programming в LocalPilot-Android

**4 ноября 2026, экспериментальный PR.** Источник идеи: ролик о работе Astra / программировании весов. Этот пакет не воспроизводит результаты авторов на MinAtar, Qwen или физическом автомобиле и не загружает их веса. Настольный LocalPilot не изменён.

## Что действительно внедрено

1. **Программирование весов без градиентного обучения.** `rl/WeightSpaceSkills.java` строит небольшие явные матрицы исходя из смысла входных признаков, а не собирает случайную сеть. Три исходные предметные задачи: `PLATFORM_RECOVERY` (Ари), `LANE_ESCAPE` (Маркет Раш), `GAP_FLIGHT` (Гошан). `Network.patch(row,col,value)` меняет ровно одно значение, сохраняет остальную матрицу, требует конечный ограниченный параметр и предоставляет diff.
2. **Изменение поведения без переобучения с нуля.** В задаче `PLATFORM_RECOVERY` исходный эксперт выбирает STAY у привлекательной, но недостижимой сверху платформы. Ремонт `patchRecovery` меняет один вес, чтобы выбрать безопасное отступление LEFT в состоянии остановки и не мешать нормальному движению. Это учебный аналог идеи «сначала откатиться, потом преодолеть препятствие», а не утверждение об обучении физического автомобиля или реальном движении Ари.
3. **Проверка на независимых сценариях.** `evaluateRetreat(seed,count)` сравнивает исходную и изменённую политику на парных сценах: нормальная траектория, допустимый обход, опасный обход и тупик, требующий начального отступления. Затрагиваемый один вес и отсутствие регрессий проверяются автоматически. Отчёт `build/reports/weight-space-skills.json` содержит `eligible_for_android=false`: симуляция не даёт разрешение на ввод.
4. **Разные игры с общим интерфейсом признаков.** Тесты проверяют первоначально запрограммированные решения для полос движения и полёта через проход. Это не обученные DQN-checkpoint; генерировать или использовать реальные жесты по чужой сети запрещено до проверки schema-совместимости и реальных наблюдений.
5. **Защита от циклов языковой модели.** `TextRepetitionGuard` отбрасывает пустые, чрезмерно длинные или повторяющиеся ответы интернет-vision-учителя в `WebLearningActivity` **до преобразования JSON в подсказку о жесте**. Это безопасная аналогия эксперимента с устранением повторов в Qwen, **но не правка весов Qwen**. Менять параметры Qwen на стороне провайдера приложение не может.
6. **Мост учебная сеть → настоящее управление (уже в предшествующем PR #72).** `PaddleTransfer` использует *ту же малую сеть*, что обучается в `PaddleWeightLab`; отдельно оценивает восемь физических вариантов; пользователь вручную переносит выдержавший тесты набор весов только в выбранную модель «Карканоида». Реальный `ArcadeController` использует перенесённые параметры лишь при подтверждённой свежей геометрии, а после первого неподтверждённого визуального движения импорт отключается. `ActionGate`, `InputPermit`, STOP, TTL, Fail-Closed и UNKNOWN не изменены.

## Репликация

JDK 17+ в корне Android-репозитория:

```bash
java tests/PaddleWeightLabVerify.java
java tests/PaddleTransferVerify.java
java tests/WeightSpaceSkillsVerify.java
java tests/TextRepetitionGuardVerify.java
```

Все эти тесты включены в `.github/workflows/android.yml`. Эксперимент `WeightSpaceSkills` можно также запустить на устройстве: **Нейросеть · учебный симулятор → Эксперимент: исправить зацикленную стратегию Ари**. Он проверяет три фиксированных seed, не посылает жесты и прерывается кнопкой STOP.

## Где границы результатов

| Идея ролика | Реализовано | Не доказано |
| --- | --- | --- |
| Создать веса из правил вместо обучения с нуля | Да, три маленьких экспертных readout-политики | Рост награды во всех настоящих играх |
| Адресно исправить локальный поведенческий тупик | Да, 1 из 12 весов, контроль отсутствия регрессий | Победа реального Ари на планшете |
| Игровое сравнение с обученными PPO / DQN | Есть исходный DQN и физические сравнения | Нет корректного общего benchmark для PPO/DQN и всех реальных игр |
| Устранить повторы Qwen | Защитный фильтр выхода у внешнего vision-учителя | Не выполнена настоящая правка MLP-слоёв Qwen |
| Перенос симулятора в настоящую модель | Включён для Карканоида из #72 через ручной opt-in | Не подтверждены 5 реальных действий на обоих устройствах |
| Сохранить полезное и откатить вредное | Immutable network patch, rollback переноса PADDLE | Нет физической acceptance-матрицы 10×2 |

## Следующая техническая задача

Отдельная версия **Jumper recovery candidate** должна сначала работать в shadow-mode на реальных последовательностях `JumperState`. Только после измерения истинного подъёма, обхода опасных платформ и подтверждённой реакции после жеста допустимо предложить перенос в `JumperPolicy`. Так же для Маркет Раш и Гошана. Стадия shadow-mode не засчитывается за игровые победы.

Для релиза требуется всё то же: десять игр × телефон и планшет × пять подряд visually-verified действий, единый HEAD SHA и проверенная подпись APK. Синтетическое улучшение ни один из этих пунктов не закрывает.
